# 基础玩法

状态：F-01～F-08、特殊盒限制及连单初始数值已确认并实现；补充执行细节见第 5～8 节。  
依据：用户确认的项目结构、术语及 F-01～F-08 规则。  
术语定义统一见 [项目术语](project_glossary.md)。本文是玩法规则事实源；本轮完成范围与验证见 [差距补齐验收](gameplay_gap_analysis.md)。

## 1. 玩法目标与核心循环

玩家在固定盒位之间搬运甜甜圈，整理出满足开放需求的同口味整盒。符合条件的盒子自动打包回收，推进需求、累计消除，并按规则触发机关和原位补位。持续处理本关有限备货，完成全部需求并清空本关所有甜甜圈后通关。

普通搬运的对象是甜甜圈。只有开局出餐、打包回收和备货补位等流程涉及整盒出入场。

## 2. 场景与关卡构成

| 区域／内容 | 基础规定 |
| --- | --- |
| 顶部需求区 | 初始化 4 个需求位置；开放／锁定状态按本关初始配置保留。只有当前开放位置的需求参与匹配。 |
| 操作区 | 固定 16 个盒位；盒子回收不删除盒位，同屏盒子不超过 16 盒。 |
| 周转盒位 | 两个周转盒位开局保持锁定；解锁后的补货规则与常规盒相同。 |
| 常规盒容量 | 每盒最多 4 颗甜甜圈，4 颗同口味称为凑齐。特殊盒另遵守自身限制。 |
| 底部出餐区域 | 首批盒子与备货盒的入场来源；备货预览不可操作。 |
| 备货队列 | 本关尚未出场的有限预设盒子队列，不占场上盒位，耗尽后停止补货。 |
| 底部辅助功能 | 保留撤回、加餐盒、置顶；与新盒子状态的具体配合见第 5 节。 |

本关盒子总数不受同屏 16 盒限制。盒位初始开放状态、各类盒子分配、需求序列、隐藏层和备货内容由关卡设计决定；开局不另外预留专用补货空位。

## 3. 关键状态边界

| 情况 | 结果 |
| --- | --- |
| 搬出盒内最后一颗甜甜圈 | 成为空盒；盒子保留，可按其自身规则继续使用。 |
| 盒内达到 4 颗同口味 | 仅表示凑齐，还需判断盒子是否可打包及是否匹配开放需求。 |
| 已凑齐但没有对应开放需求 | 等待需求；盒子原位保留，不计消除、不补货、不触发机关。 |
| 可打包的盒子凑齐且匹配开放需求 | 整盒打包回收，原处成为空盒位，成功回收计 1 次消除。 |
| 符合补位规则且队列仍有备货 | 队首整盒进入刚腾出的原盒位。 |
| 不符合补位规则或备货耗尽 | 不补货；回收后留下的空盒位不能直接接收甜甜圈。 |

**“等待需求”规定的是回收条件，不额外附加新的锁定取放规则。** 等待中的盒子仍按普通搬运规则及自身特殊限制判断取放；不能仅因它正在等待就禁止取出。

## 4. 基础玩法与交互规则

### 4.1 F-01 开局出餐

1. 初始化 4 个需求位置和 16 个盒位，保持各自初始开放／锁定状态。
2. 从底部出餐区域通过动画，将首批盒子摆入当前可用的常规盒位；两个周转盒位保持锁定。
3. 尚未出场的盒子留在本关有限备货队列中，不额外占用盒位。
4. 开局不另外预留专用补货空位。

例如，本关有 25 个盒子，先摆入当前可用的盒位，其余通过后续回收补位陆续出场；整关处理数量可超过 16 盒，但同屏始终不超过 16 盒。

### 4.2 F-02 拖拽、点击、成组搬运与自动拆分

1. 玩家按住来源盒顶部的甜甜圈，拖到目标盒后松手，移动顶部已显示口味的连续组；拖动时食物跟随指针，合法目标高亮。也保留先点击来源盒选中、再点击目标盒放入的操作。
2. 普通目标盒必须有空位，且为空盒或顶部为同口味。空盒位没有盒子，不能作为接收甜甜圈的目标盒。
3. 来源盒顶部连续同口味的甜甜圈可以成组移动，也可以拆分。
4. 目标容量足够时，整组移入；容量不足时，自动放入可容纳的数量，其余留在来源盒。
5. 目标只剩一个坑位时，默认拆出一颗放入。
6. 取放同时遵守特殊盒自身限制；不满足条件的搬运不能改变盒内内容。

例如，两颗同口味甜甜圈连在一起，目标盒只剩一个坑位，则移入一颗，另一颗留在来源盒。

拖动预览不改变盒内数据，松手且目标有效时才提交一次搬运。拖到原盒、空白处、空盒位、满盒或受限盒均不执行搬运；取消、失焦、隐藏、暂停与离树后恢复原状态。鼠标与触摸共用规则，多指不能接管当前拖动，触摸模拟的鼠标事件不重复结算。

### 4.3 F-03 明牌与隐藏层

- 一关可以全部明牌，也可以有隐藏层；明牌与隐藏层可在同一关并存。
- 隐藏甜甜圈露到顶部时揭示口味。
- 刚揭示的甜甜圈即使与本次搬运口味一致，也不在同一次操作中继续自动搬走。

本次可搬运的连续组以操作开始时顶部已显示口味的部分为边界，不能跨过隐藏层继续搬运。

### 4.4 F-04 需求匹配、等待与打包回收

只有同时满足以下条件，才自动打包回收：

- 盒内已有 4 颗同口味甜甜圈。
- 该盒当前可以打包，不受未解除的盒子限制。
- 当前开放的需求位置中存在对应口味需求。

符合条件后整盒打包，从界面顶部弹出回收，完成对应需求。锁定位置的隐藏需求不能提前参与匹配。

已凑齐但未匹配需求的盒子在原位等待，不释放盒位、不补货、不计消除，也不触发冰冻盒解冻或数字盖盒减数。等待状态本身不改变取放权限。

### 4.5 F-05 需求更新与自动连续回收

1. 成功打包回收后，对应需求位置更新后续需求；其他未完成的位置保持不变。
2. 检查场上已凑齐且可以打包的盒子。
3. 若有盒子匹配新需求，无需再次点击或搬运，自动打包回收。
4. 继续更新该需求并检查后续匹配，直到没有新的匹配盒子。
5. 每次回收分别完成对应需求、计入消除；同一个需求或同一盒回收不得被重复结算。

**必须支持的典型场景：**

需求池当前开放草莓和巧克力；场上已凑齐一盒蓝莓和一盒橙子。草莓所在需求位置的后续顺序为蓝莓、橙子。

| 步骤／触发 | 结果 | 需求池变化 |
| --- | --- | --- |
| 初始 | 蓝莓盒和橙子盒原位等待。 | 草莓、巧克力仍未完成。 |
| 草莓盒凑齐并匹配需求 | 草莓盒打包回收。 | 草莓需求更新为蓝莓。 |
| 新需求匹配已有蓝莓盒 | 蓝莓盒自动打包回收。 | 蓝莓需求更新为橙子。 |
| 新需求匹配已有橙子盒 | 橙子盒自动打包回收。 | 继续按后续需求检查匹配。 |

巧克力需求始终保持不变。以上连续回收共计 3 次消除，并计入连单。正式连单机制包含额外金币和钻石奖励，详见第 7 节；奖励使用用户另行确认的初始档位。示例仅展示开放的两个需求，其余需求位置不影响本例。橙子仅为规则举例；当前正式素材仍为草莓、巧克力、抹茶、蓝莓，验收使用抹茶替代橙子。

### 4.6 F-06 原位出餐补位

- 可补位盒子成功打包回收后，从底部出餐区域将备货队首整盒补入刚腾出的原盒位。
- 每次补位只消耗对应的一个备货盒，不移动或重排其他盒子。
- 搬空盒子不补货；凑齐但等待需求的盒子不补货。
- 单颗暂存盒位不参与补位。周转盒解锁后，补货规则与常规盒相同。
- 备货预览不可操作；队列耗尽即停止补货，不凭空生成新盒子。
- 新补入的盒子不追溯享受入场前发生的消除所带来的开盖或解冻效果。

需求更新、机关触发、补货均来自本次真实的回收事件。展示动画可以衔接，但不能让同一次回收产生重复补位或重复计数。连续回收中的每一次真实回收均独立适用这些规定。

### 4.7 F-07 消除计数与机关触发

| 事件 | 是否回收／计消除 | 是否触发补货和机关 |
| --- | --- | --- |
| 匹配开放需求并成功打包回收 1 盒 | 是，计 1 次。 | 按该盒的补位规则处理；触发对应机关效果。 |
| 连续成功回收多盒 | 每盒分别计 1 次。 | 每次回收分别触发。 |
| 搬空盒、凑齐后等待需求、暂存盒装满 | 否。 | 不触发。 |
| 数字盖盒开盖、冰冻盒破冰 | 本身不计消除、不回收。 | 本身不产生新的补货或机关计数。 |
| 周转盒搬空 | 否，空盒保留。 | 不触发；只有成功打包后才回收。 |

后期机关启用时，每成功回收 1 盒，当前在场的所有数字盖盒各减 1；若有冰冻盒，则从当前在场的冰冻盒中解冻 1 盒。玩家搬运促成的回收和需求更新引发的自动回收均适用。

开盖、解冻和打包回收是不同事件。若解除限制后又发生满足 F-04 的实际打包回收，该次回收按自身事件计数，不能把解除限制本身计为消除。

### 4.8 F-08 通关

完成本关全部需求，并清空本关所有甜甜圈后通关；空盒可以保留。不能仅因当前场上没有甜甜圈，就忽略仍未处理的需求或备货而判定通关。

全部需求包含本关尚未完成的后续需求，不仅是当前开放位置显示的需求；所有甜甜圈包含场上各类盒子与尚未出场备货中的甜甜圈。

## 5. 辅助功能与特殊盒

用户已确认：加餐盒解锁周转盒；数字盖未归零、冰冻未解除时禁止取放和打包；每次消除按盒位顺序解冻一个冰冻盒；需求位置按关卡配置的消除次数解锁。

| 类别／功能 | 当前规则 |
| --- | --- |
| 周转盒 | 开局两个盒位锁定；每次加餐盒启用编号最小的未开放周转盒位，生成空盒，不消耗备货，不增加第 17 格。启用后容量 4；搬空保留，打包后按常规原位补货。 |
| 单颗暂存 | 占用固定 16 格中的一个位置，容量 1，取放仍遵守同味／空盒原则；不回收、不补货、不触发机关。第二关包含该类型。 |
| 数字盖盒 | 未归零时禁止取出、放入、置顶和打包；每次真实回收使所有已在场数字盖减 1，归零开盖。初始数值由关卡配置。 |
| 冰冻盒 | 未解冻时禁止取出、放入、置顶和打包；每次真实回收按盒位从左到右、从上到下解冻 1 个已在场冰冻盒。 |
| 撤回 | 恢复上一次成功搬运、加餐盒或置顶前的完整状态，包括明暗、需求、备货、机关、盒子与本关奖励；整串自动回收一起恢复。返还该操作消耗的其他道具，本次撤回次数不返还。开局不是可撤回的玩家操作。 |
| 置顶 | 先选可操作餐盒，再选已揭示且会改变排列的一颗甜甜圈移到顶部；隐藏层不展示口味、不可选。取消、无效选择或不改变排列不扣次数。 |
| 暂无合法搬运 | 提示可撤回、启用周转盒或重开，不直接判负；设置菜单保留重开与选关。 |

现有三关的初始道具次数均为撤回 3、加餐盒 2、置顶 3，可通过配置调整；这不是后续所有关卡的固定平衡要求。当前搬运按目标容量自动拆分，没有额外的手动数量选择面板。

## 6. 确定性结算与界面

同一时刻多个盒子可回收时，优先编号最小的盒位；同口味需求并存时优先最左侧开放需求。一次真实回收依次执行：

1. 移走该盒，推进对应需求，消除数加 1。
2. 当前已在场数字盖各减 1；按顺序解冻 1 个已在场冰冻盒。
3. 根据新的消除数开放到达阈值的需求与常规盒位；新开放盒不承接该次历史机关效果。
4. 有备货且原盒位可补位时，队首整盒补到原位。
5. 重新检查所有可打包盒子，继续实际回收，直到没有新匹配。
6. 统计本次操作的真实回收盒数，按第 7 节结算一次连单奖励。

每个需求位置有自己的后续序列。常规盒位开放阈值和需求开放阈值均由关卡配置；周转盒位只由加餐盒启用。限制解除后按规则揭示露顶隐藏层；隐藏层不要求提前全部揭示才判定真实口味是否凑齐。

界面按每个事件之后的快照依次展示：首批从底部入场、成组移动、整盒向顶部回收、机关变化、原位补入和连单。动画只展示已结算结果，不再次发奖、消除或补货。失焦、暂停、隐藏、离树中断动效时，清理临时精灵与选中态，直接显示已提交的最终状态；恢复后可继续操作。

操作区固定 4×4。顶部四需求位置显示口味、锁定阈值或完成状态；底部预览真实备货队首两盒，数量单位为“盒”，不可操作。空盒位保留淡轮廓，与可接收食物的空盒区分。

## 7. 连单与奖励

用户确认的初始规则：**一次操作引发连续回收即计连单**，包含新需求、机关解除或新补入盒子引发的自动回收。跨两次玩家操作不累计；一次操作内按真实回收总数只发放最高匹配档位，不将各档叠加。

| 同次回收盒数 | 额外金币 | 额外钻石 |
| --- | --- | --- |
| 0～1 | 0 | 0 |
| 2 | 5 | 0 |
| 3 | 10 | 1 |
| 4 及以上 | 20 | 2 |

数值保存在各关 `combo_rewards` 配置中。奖励在该次操作全部自动回收结束后结算；撤回恢复前值，重做不重复累加。开局若由配置触发自动连续回收，同样按一批结算；当前三关开局均无自动回收。

当前金币和钻石是**本关累计奖励**，界面明确标记“本关奖励”，结算页汇总。重开或切关清零；账号资产、跨关保存与商城不在本次基础玩法范围内。

## 8. 当前内容与后续边界

已接入三关，具体布局、口味序列、备货与机关参数以 [关卡目录](../Coding/godot/game_content/donuts/levels/catalog.json) 所指配置为唯一人工事实源。第一关覆盖普通成组排序，保留 4 个普通空盒、8 单需求；第二关保留 3 个普通空盒和 1 个单颗暂存盒、10 单需求，仅加入少量隐藏层。两关四需求均开放。第三关使用 25 个预设盒及变化口味的独立需求序列，覆盖数字盖、冰冻、需求锁定、等待、自动连收与奖励。

关卡必须保持各口味供需匹配，并提供无需道具可通关的完整解。新手关同时保留明显的普通空盒和未满盒，保证有多个合法落点；不能只凭存在一条固定解认定难度合理。普通空盒有实际容器，可自由周转，与不存在容器的空盒位不同；它不是专用补货空位，补货仍遵守 F-06。前两关密度与验证见 [数值调整记录](early_level_balance.md)。正式难度曲线、更多关卡、声音及跨关经济仍可后续扩展；本轮已确认规则没有待确认的实现分支。
