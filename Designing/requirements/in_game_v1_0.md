## 1. 产品概述与本次目标

游戏为竖屏的甜甜圈整理消除＋甜品店装修养成，不出现人物。玩家将甜甜圈整理为4颗同口味的一盒，匹配当前订单后打包回收，通过游戏获得金币和钻石，用于装修自己的甜品店。

本次先开发局内界面，让玩家能够看懂当前需求、辨认盒内甜甜圈、完成基础搬运，并看到打包回收与出餐补位的结果。验收重点是界面结构、状态表达及基础流程，不以完成全部游戏系统为前提。

### 1.1 本次交付范围

| 范围 | 本次交付要求 |
| --- | --- |
| 局内页面 | 完成顶部需求池、中部4×4操作区、底部出餐区域，适配竖屏和安全区。 |
| 基础对象与状态 | 展示常规盒、甜甜圈堆叠、明牌与隐藏层、选中状态、满盒等待需求、空盒与空盒位。 |
| 基础交互 | 支持点击来源盒和目标盒、同味成组搬运、容量不足时自动拆分、隐藏层揭示。 |
| 核心流程表现 | 可演示开局摆盒、需求匹配、打包回收、需求更新、自动连续回收、有限队列补位及通关反馈。 |
| 锁定位置 | 显示2个锁定需求位置和2个锁定周转盒位；能展示解锁后的已确认状态，但不接入未确定的解锁方式。 |
| 功能入口 | 按“撤回、加餐盒、置顶”的顺序保留入口。本次不据演示代码确定正式道具效果、次数或消耗。 |

本次可以使用本地演示数据驱动页面和交互，但必须符合本文基础规则。演示关数值不视为正式关卡配置。

## 2. 术语与固定约束

### 2.1 术语

| 术语 | 定义 |
| --- | --- |
| 盒位 | 操作区内固定的位置；盒子回收后，该位置仍保留。 |
| 空盒 | 有盒子、没有甜甜圈；搬空后仍留在原位，可按盒子规则继续使用。 |
| 空盒位 | 原盒子已被回收、当前没有盒子的位置；与可接收甜甜圈的空盒不同。 |
| 来源盒／目标盒 | 本次取出甜甜圈的盒子／本次接收甜甜圈的盒子。搬运对象是甜甜圈。 |
| 凑齐 | 一个盒子内已有4颗同口味甜甜圈，不等同于成功打包。 |
| 等待需求 | 已凑齐，但当前开放需求中没有对应口味；盒子继续留在原位。 |
| 打包回收／消除 | 可打包的盒子凑齐且匹配当前开放需求，整盒打包并回收；成功回收1盒计1次消除。 |
| 备货队列 | 本关尚未出场的有限预设盒子队列，由底部出餐区域依次补入。 |

### 2.2 固定约束

| 项目 | 已确认约束 |
| --- | --- |
| 需求池 | 共4个位置；初始2个开放、口味已知，另2个锁定、口味未知。 |
| 操作区 | 4行×4列，共16个盒位；包含14个常规盒位和2个需解锁的周转盒位。 |
| 同屏上限 | 所有关卡同屏最多16个盒子。解锁周转盒不会新增第17或第18个盒位。 |
| 常规盒 | 容量4颗；初始可装1—4颗甜甜圈。 |
| 周转盒 | 解锁后与常规盒相同，容量4颗；不限取放次数，沿用常规取放、打包和补货规则。 |
| 口味与颜色 | 不同颜色对应不同口味；颜色与口味表达在需求池、场上和备货预览中保持一致。 |
| 连体与拆分 | 贯穿整个游戏的基础机制，不是后期才出现的限制。 |
| 关卡总量 | 可超过16盒，通过有限备货队列陆续出场；25盒仅为说明用例，不是固定配置。 |

## 3. 页面结构与视觉需求

页面从上到下分为三个板块。顶部关卡标签仅显示关卡，不显示难度；其下为需求池。具体盒位数量和需求位置数量以本文为准。

| 编号 | 区域／组件 | 内容与表现要求 |
| --- | --- | --- |
| UI-01 | 顶部：关卡与需求池 | 关卡标签下缘与需求池上缘保留20px设计间距。需求池固定4格；开放位置以甜甜圈口味图标表达，锁定位置不展示真实口味。 |
| UI-02 | 中部：游戏操作区 | 固定4×4结构；盒子在原盒位内整理，回收与补位不重排其他盒子。2个锁定周转盒位包含在16格内。 |
| UI-03 | 盒子与甜甜圈 | 展示盒内堆叠关系、顶部可搬运口味和隐藏层。纸盒前沿避免遮挡甜甜圈，玩家能区分盒子是否为空、是否凑齐、是否在等待需求。 |
| UI-04 | 底部：出餐区域 | 承担开局摆盒和后续补位的动画起点；显示备货预览。预览仅用于观察，不能点击搬运，也不占中部盒位。 |
| UI-05 | 功能入口 | 横向顺序固定为：撤回、加餐盒、置顶。入口可见不等于对应功能已完成；未接入功能不得表现为已成功执行。 |
| UI-06 | 整体风格与适配 | 延续已选甜品风格，竖屏、无人物。背景满屏；需求池、盒子、按钮等重要内容避开刘海和底部手势区。 |
| UI-07 | 素材比例 | 甜甜圈、盒子和备货预览等比缩放，避免压扁或拉伸；不同区域同一口味保持一致。 |

20px为设计间距，适配时保持对应设计关系。整页需要同时容纳三个板块，避免关键操作区域被遮挡或相互重叠。

### 3.1 需求池状态

| 状态 | 显示 | 行为 |
| --- | --- | --- |
| 开放、有需求 | 对应甜甜圈口味图标 | 参与需求匹配。 |
| 锁定 | 锁定状态，不显示具体口味 | 不参与当前需求匹配。 |
| 解锁后 | 揭示该位置口味 | 作为开放需求参与匹配。 |
| 对应订单完成 | 更新该位置的后续需求 | 其他未完成的需求位置保持不变。 |

### 3.2 操作区状态

| 状态 | 界面表达与交互要求 |
| --- | --- |
| 普通可操作盒 | 可辨认甜甜圈层次及顶部口味，按照取放规则响应操作。 |
| 来源盒已选中 | 有清楚的选中反馈；玩家可以识别当前搬运来源。 |
| 无效目标 | 口味不符、容量不足以放入任何一颗或处于锁定状态时，不执行搬运、不改变盒内数据，并给予反馈。 |
| 隐藏层 | 未露出时不泄露口味；露到顶部时揭示。 |
| 凑齐且等待需求 | 仍占原盒位，可与成功打包状态区分；不播放成功回收反馈。 |
| 搬空后的空盒 | 保留盒子；不得误显示为已回收或自动补入新盒。 |
| 已回收后的空盒位 | 原盒已离场，等待原位补货；队列耗尽后可保持无盒状态。 |
| 锁定周转盒位 | 占用预留盒位，不能取放；解锁后按普通容量4的盒子显示和操作。 |

“等待需求”在本文中规定的是回收条件，不额外附加新的锁定取放规则。

## 4. 基础玩法与交互规则

### 4.1 F-01 开局出餐

1. 初始化4个需求位置和16个盒位，保持各自初始开放／锁定状态。
2. 从底部出餐区域通过动画，将首批盒子摆入当前可用的常规盒位；两个周转盒位保持锁定。
3. 尚未出场的盒子留在本关有限备货队列中，不额外占用盒位。
4. 开局不另外预留专用补货空位。

例如，本关有25个盒子，先摆入当前可用的盒位，其余通过后续回收补位陆续出场；整关处理数量可超过16盒，但同屏始终不超过16盒。

### 4.2 F-02 点击、成组搬运与自动拆分

1. 玩家先点击来源盒，再点击目标盒，移动来源盒顶部已显示口味的甜甜圈。
2. 普通目标盒必须有空位，且为空盒或顶部为同口味。
3. 来源盒顶部连续同口味的甜甜圈可以成组移动，也可以拆分。
4. 目标容量足够时，整组移入；容量不足时，自动放入可容纳的数量，其余留在来源盒。
5. 目标只剩一个坑位时，默认拆出一颗放入。
6. 取放同时遵守特殊盒自身限制；不满足条件的搬运不能改变盒内内容。

例如，两颗同口味甜甜圈连在一起，目标盒只剩一个坑位，则移入一颗，另一颗留在来源盒。

### 4.3 F-03 明牌与隐藏层

- 一关可以全部明牌，也可以有隐藏层；明牌与隐藏层可在同一关并存。
- 隐藏甜甜圈露到顶部时揭示口味。
- 刚揭示的甜甜圈即使与本次搬运口味一致，也不在同一次操作中继续自动搬走。

### 4.4 F-04 需求匹配、等待与打包回收

只有同时满足以下条件，才自动打包回收：

- 盒内已有4颗同口味甜甜圈。
- 该盒当前可以打包，不受未解除的盒子限制。
- 当前开放的需求位置中存在对应口味需求。

符合条件后整盒打包，从界面顶部弹出回收，完成对应需求。锁定位置的隐藏需求不能提前参与匹配。

已凑齐但未匹配需求的盒子在原位等待，不释放盒位、不补货、不计消除，也不触发冰冻盒解冻或数字盖盒减数。

### 4.5 F-05 需求更新与自动连续回收

1. 成功打包回收后，对应需求位置更新后续需求；其他未完成的位置保持不变。
2. 检查场上已凑齐且可以打包的盒子。
3. 若有盒子匹配新需求，无需再次点击或搬运，自动打包回收。
4. 继续更新该需求并检查后续匹配，直到没有新的匹配盒子。
5. 每次回收分别完成对应需求、计入消除；同一个需求或同一盒回收不得被重复结算。

**必须支持的典型场景：**

需求池当前开放草莓和巧克力；场上已凑齐一盒蓝莓和一盒橙子。草莓所在需求位置的后续顺序为蓝莓、橙子。

| 步骤 | 触发结果 | 需求池变化 |
| --- | --- | --- |
| 初始 | 蓝莓盒和橙子盒原位等待 | 草莓、巧克力仍未完成。 |
| 草莓盒凑齐并匹配需求 | 草莓盒打包回收 | 草莓需求更新为蓝莓。 |
| 新需求匹配已有蓝莓盒 | 蓝莓盒自动打包回收 | 蓝莓需求更新为橙子。 |
| 新需求匹配已有橙子盒 | 橙子盒自动打包回收 | 继续按后续需求检查匹配。 |

巧克力需求始终保持不变。以上连续回收共计3次消除，并计入连单。正式连单机制包含额外金币和钻石奖励，详见第7节；本次不据演示数据确定奖励数值。

### 4.6 F-06 原位出餐补位

- 可补位盒子成功打包回收后，从底部出餐区域将备货队首整盒补入刚腾出的原盒位。
- 每次补位只消耗对应的一个备货盒，不移动或重排其他盒子。
- 搬空盒子不补货；凑齐但等待需求的盒子不补货。
- 单颗暂存盒位不参与补位。周转盒解锁后，补货规则与常规盒相同。
- 备货预览不可操作；队列耗尽即停止补货，不凭空生成新盒子。
- 新补入的盒子不追溯享受入场前发生的消除所带来的开盖或解冻效果。

需求更新、机关触发、补货均来自本次真实的回收事件。展示动画可以衔接，但不能让同一次回收产生重复补位或重复计数。

### 4.7 F-07 消除计数与机关触发

| 事件 | 是否回收／计消除 | 是否触发补货和机关 |
| --- | --- | --- |
| 匹配开放需求并成功打包回收1盒 | 是，计1次 | 按该盒的补位规则处理；触发对应机关效果。 |
| 连续成功回收多盒 | 每盒分别计1次 | 每次回收分别触发。 |
| 搬空盒、凑齐后等待需求、暂存盒装满 | 否 | 不触发。 |
| 数字盖盒开盖、冰冻盒破冰 | 本身不计消除、不回收 | 本身不产生新的补货或机关计数。 |
| 周转盒搬空 | 否，空盒保留 | 不触发；只有成功打包后才回收。 |

后期机关启用时，每成功回收1盒，当前在场的所有数字盖盒各减1；若有冰冻盒，则从当前在场的冰冻盒中解冻1盒。玩家搬运促成的回收和需求更新引发的自动回收均适用。

### 4.8 F-08 通关

完成本关全部需求，并清空本关所有甜甜圈后通关；空盒可以保留。不能仅因当前场上没有甜甜圈，就忽略仍未处理的需求或备货而判定通关。

## 5. 动画与反馈要求

| 动作 | 起点与结果 | 验收重点 |
| --- | --- | --- |
| 开局摆盒 | 底部出餐区 → 中部可用盒位 | 有出餐、摆入的动画表现，盒子最终落入正确盒位。 |
| 搬运 | 来源盒顶部 → 目标盒 | 移动口味及数量与规则一致；来源剩余内容清楚可见。 |
| 隐藏层揭示 | 隐藏层露到顶部 → 显示真实口味 | 不提前显示，也不在同一次搬运中额外搬走。 |
| 成功打包 | 匹配需求的盒子 → 界面顶部回收 | 有整盒打包与离场表现；等待需求的满盒不得使用该反馈。 |
| 需求更新 | 完成的需求位置 → 后续需求 | 更新的是对应位置，未完成的位置保持原状。 |
| 自动连续回收 | 新需求匹配场上已有满盒 | 自动衔接，无需再次点击；每盒分别结算。 |
| 补位 | 底部出餐区 → 刚回收的原盒位 | 不抢占其他盒位，不重排其他盒子。 |
| 无效操作 | 未满足放入或取出条件 | 给出可辨认反馈，原盒、目标盒及备货数据不变。 |
| 通关 | 全部需求和甜甜圈处理完毕 | 明确反馈本关完成，不编造尚未确定的奖励。 |

动画不得让一次有效操作被重复执行，也不得因视觉层与数据不同步导致数量丢失、重复或超过盒子容量。本节规定动作方向与结果，不固定未经确认的动画时长、特效强度或音效方案。

## 6. 首期验收标准

开发交付可运行的局内页面、对应工程源码及启动方式。使用符合规则的演示数据完成以下检查；界面验收与后续正式关卡、平台接入验收分开进行。

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 打开局内页面 | 竖屏、无人物；上中下三个板块完整，关卡标签不显示难度，需求池与标签保持20px设计间距。 |
| AC-02 | 检查需求池 | 正好4格；初始2格显示口味、2格锁定且不泄露口味；锁定需求不参与匹配。 |
| AC-03 | 检查操作区 | 正好4×4共16格，其中2格为锁定周转盒位；不会额外增加盒位。 |
| AC-04 | 开局有超过16盒的关卡数据 | 首批通过出餐动画进入可用盒位，其余留在备货队列；同屏数量不超过16。 |
| AC-05 | 同味成组搬运 | 目标容量足够时移入顶部连续同味组；源、目标数量准确。 |
| AC-06 | 目标只剩1个坑位 | 从多颗同味组中自动移入1颗，其余保留；盒子容量不超过4。 |
| AC-07 | 不同味目标、满盒或锁定目标 | 不发生搬运，内容和队列不变，并有操作反馈。 |
| AC-08 | 搬走顶部后露出隐藏层 | 正确揭示口味，刚揭示的甜甜圈留待下一次操作。 |
| AC-09 | 凑齐非当前需求的4颗同味 | 保留在原盒位，不打包、不计消除、不补货。 |
| AC-10 | 凑齐当前开放需求 | 自动整盒打包并从顶部回收，对应需求更新，其他需求不变。 |
| AC-11 | 草莓 → 蓝莓 → 橙子示例 | 已等待的蓝莓盒、橙子盒依次自动回收，共计3次消除，巧克力需求不变。 |
| AC-12 | 回收有备货的盒子 | 队首整盒补入原盒位，队列减少1盒；其他位置不变。 |
| AC-13 | 搬空盒子／备货耗尽 | 搬空后原盒保留且不补货；队列耗尽后不再生成备货。 |
| AC-14 | 展示解锁后的状态 | 需求位置显示口味并可匹配；周转盒容量4颗、取放不限次、正常打包补货；盒位总数不变。可用演示状态验收，不要求接入正式解锁方式。 |
| AC-15 | 本关结束 | 只有全部需求完成且本关甜甜圈清空才通关；允许保留空盒。 |
| AC-16 | 检查入口与竖屏适配 | “撤回、加餐盒、置顶”顺序正确；不同竖屏尺寸下关键区域不遮挡、不溢出安全区，盒子和甜甜圈保持比例。 |
| AC-17 | 连续点击、动画与状态衔接 | 不重复搬运、回收或补货，不出现一盒超过4颗或甜甜圈丢失、复制。 |

本次完成上述内容，即可交由策划体验局内布局和基础操作。第7、8节不作为本次全部实现的前置条件。

## 7. 后续扩展机制（已确认，非首期完整实现范围）

以下机制随难度增加按关卡加入，不属于每局默认流程，也不要求同时出现。

| 编号 | 机制 | 已确认规则与后续界面要求 |
| --- | --- | --- |
| EX-01 | 数字盖盒 | 盒内有4颗甜甜圈。盒盖数字表示还需成功消除多少盒才能打开；每成功回收1盒，当前在场的所有数字盖盒各减1，归零开盖。未开盖时不能取放，内部口味隐藏。与常规盒采用相同外接宽高；盖面使用统一底色，仅保留数字。 |
| EX-02 | 冰冻盒 | 初始仅1层冰，通过透明盖和冰冻效果表现；可看到口味，冻结期间不能取放。每成功回收1盒，从当前在场的冰冻盒中解冻1盒。 |
| EX-03 | 单颗暂存盒 | 只能装1颗，视觉上更短、更窄、边缘更低。装满不打包、不计消除、不补货；盒子保留，甜甜圈最终需搬回常规盒参与消除。 |
| EX-04 | 炸弹盒 | 带时间倒计时，右下角以紧凑数字显示。在时限内按需求规则成功打包回收炸弹所在盒，才解除炸弹；搬空不能解除。归零且未解除时，盒子与甜甜圈爆炸，本关直接失败。 |
| EX-05 | 空订单盒 | 只能放入甜甜圈，放入后不能取出；未装满时同样适用。 |
| EX-06 | 固定颜色盒 | 只能放入指定颜色的甜甜圈，空盒时也不能放入其他颜色。 |
| EX-07 | 底部置顶盒 | 每次成功从该盒搬出甜甜圈后，将剩余甜甜圈中最底部的一颗移到顶部，其余保持相对顺序。详见7.1。 |
| EX-08 | 连单奖励 | 短时间内连续成功打包回收，可额外获得更多金币和钻石；包含需求更新引发的自动连续回收。按真实成功回收判定，不限制期间的搬运次数，也不要求每次搬运都打包成功。 |

### 7.1 底部置顶盒

此功能由盒子自身自动触发，与底部“置顶”功能入口分开描述；不能据此推定置顶道具的使用规则。

- 只有从带有该功能的来源盒成功搬出甜甜圈才触发；仅放入、选中或搬运失败不触发。
- 先完成本次搬运，再将来源盒剩余甜甜圈中最底部的一颗移到顶部，其余保持相对顺序。
- 无论一次移出一颗还是一组，只触发一次；成组与拆分仍沿用基础规则。
- 新置顶的甜甜圈不在本次操作中继续自动搬出；若为隐藏层，则揭示口味。
- 搬空后无需置顶；仅剩一颗时排列不变。
- 置顶本身不计消除，不直接触发补位、解冻或数字盖盒减数。

例如，来源盒从上到下为“草莓、巧克力、橙子、蓝莓”。成功搬出草莓后，蓝莓置顶，排列变为“蓝莓、巧克力、橙子”，下一次可搬运的是蓝莓。

### 7.2 炸弹计时

- 出现且可操作时开始计时。
- 教学、入场、设置暂停、切后台和系统结算期间暂停。
- 普通移动不刷新时间，重开恢复初始时限。
- 倒计时归零前，系统已接受且满足打包条件的操作，优先判定成功，不因打包动画耗时导致失败。

### 7.3 机关联动边界

只有匹配需求池并成功打包回收，才驱动数字盖盒减数和冰冻盒解冻。凑齐但等待需求、开盖、破冰、暂存盒装满、搬空盒子和底部置顶本身均不能代替成功回收。

新补入的盒子仅接受其入场后发生的消除效果，不追溯此前事件。具体机制只在被关卡启用时生效，不得作为所有关卡默认规则。
