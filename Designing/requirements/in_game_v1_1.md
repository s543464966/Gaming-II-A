## 1. 产品概述与本次目标

游戏为竖屏的甜甜圈整理消除＋甜品店装修养成，不出现人物。玩家将甜甜圈整理为4颗同口味的一盒；首次归纳成功可推动后期带数字机关，匹配当前需求后才打包回收。金币用于基础装修，钻石用于可选的特色外观。

本次先开发局内界面，让玩家能够看懂当前需求、辨认盒内甜甜圈、完成基础搬运，并看到打包回收与出餐补位的结果。验收重点是界面结构、状态表达及基础流程，不以完成全部游戏系统为前提。

### 1.1 本次交付范围

| 范围 | 本次交付要求 |
| --- | --- |
| 局内页面 | 完成顶部需求池、中部4×4操作区、底部出餐区域，适配竖屏和安全区。 |
| 基础对象与状态 | 展示常规盒、甜甜圈堆叠、明牌与隐藏层、选中状态、首次归纳完成、满盒等待需求、空盒与空盒位。 |
| 基础交互 | 支持点击来源盒和目标盒、同味成组搬运、容量不足时自动拆分、隐藏层揭示；识别每只实体盒首次归纳完成。 |
| 核心流程表现 | 可演示开局摆盒、归纳反馈、需求匹配、打包回收、需求更新、自动连续回收、有限队列补位及通关反馈。 |
| 锁定位置 | 显示2个锁定需求位置和2个锁定周转盒位；能展示解锁后的已确认状态，但不接入未经确定的解锁方式。 |
| 功能入口 | 底部按“撤回、加餐盒、置顶”的顺序保留入口；功能未接入时有明确不可用反馈，不显示虚构的正式次数或消耗。 |

本次可以使用本地演示数据驱动页面和交互，但必须符合本文基础规则。演示关数值不视为正式关卡配置。

## 2. 术语与固定约束

### 2.1 术语

| 术语 | 定义 |
| --- | --- |
| 盒位 | 操作区内固定的位置；盒子回收后，该位置仍保留。 |
| 实体盒 | 一只具体的盒子。补货入同一盒位的是另一只实体盒；归纳完成按实体盒计，不能按盒位重复计。 |
| 空盒 | 有盒子、没有甜甜圈；搬空后仍留在原位，可按盒子规则继续使用。 |
| 空盒位 | 原盒子已被回收、当前没有盒子的位置；与可接收甜甜圈的空盒不同。 |
| 来源盒／目标盒 | 本次取出甜甜圈的盒子／本次接收甜甜圈的盒子。搬运对象是甜甜圈。 |
| 凑齐 | 一个盒子内已有4颗同口味甜甜圈，是状态，不等同于成功打包。 |
| 归纳完成 | 玩家有效搬运后，一只实体盒首次由未归纳状态变为4颗同口味；即使没有当前需求也成立。开局、补货已凑齐和同盒重复凑齐不重新触发。 |
| 等待需求 | 已凑齐，但当前开放需求中没有对应口味；盒子继续留在原位。 |
| 打包回收／消除 | 可打包的盒子凑齐且匹配当前开放需求，整盒打包并回收；成功回收1盒计1次消除。 |
| 备货队列 | 本关尚未出场的有限预设盒子队列，由底部出餐区域依次补入。 |

### 2.2 固定约束

| 项目 | 已确认约束 |
| --- | --- |
| 需求池 | 共4个位置；初始2个开放、口味已知，另2个锁定、口味未知。 |
| 首期有效需求 | 可交付的基础演示关把全部需要完成的需求放在2个开放位置的有限序列中；锁定位置不参与匹配，也不阻碍本次通关。 |
| 操作区 | 4行×4列，共16个盒位；包含14个常规盒位和2个需解锁的周转盒位。 |
| 同屏上限 | 所有关卡同屏最多16个盒子。解锁周转盒不会新增第17或第18个盒位。 |
| 常规盒 | 容量4颗；初始可装1—4颗甜甜圈。 |
| 周转盒 | 解锁后与常规盒相同，容量4颗；不限取放次数，沿用常规取放、打包和补货规则。 |
| 口味与颜色 | 不同颜色对应不同口味；颜色与口味表达在需求池、场上和备货预览中保持一致。 |
| 连体与拆分 | 贯穿整个游戏的基础机制，不是后期才出现的限制。 |
| 关卡总量 | 可超过16盒，通过有限备货队列陆续出场；25盒仅为说明用例，不是固定配置。 |
| 关卡数据 | 场上加备货中每种口味的甜甜圈总数为4的倍数，对应有效需求中该口味的盒数；演示关要有无需道具和未定义解锁流程的通关路径。 |

## 3. 页面结构与视觉需求

页面从上到下分为三个板块。顶部关卡标签仅显示关卡，不显示难度；其下为需求池。具体盒位数量和需求位置数量以本文为准。

| 编号 | 区域／组件 | 内容与表现要求 |
| --- | --- | --- |
| UI-01 | 顶部：关卡与需求池 | 关卡标签下缘与需求池上缘保留20px设计间距。需求池固定4格；开放位置以甜甜圈口味图标表达，锁定位置不展示真实口味。局内顶部不增设金币、钻石余额。 |
| UI-02 | 中部：游戏操作区 | 固定4×4结构；盒子在原盒位内整理，回收与补位不重排其他盒子。2个锁定周转盒位包含在16格内。 |
| UI-03 | 盒子与甜甜圈 | 展示盒内堆叠关系、顶部可搬运口味和隐藏层。纸盒前沿避免遮挡甜甜圈，玩家能区分盒子是否为空、是否凑齐、是否在等待需求。 |
| UI-04 | 底部：出餐区域 | 包含出餐台、备货预览及3个功能入口。出餐台承担开局摆盒和后续补位的动画起点；预览只供观察，不能点击搬运，也不占中部盒位。 |
| UI-05 | 功能入口 | 从左到右固定为：撤回、加餐盒、置顶。入口可见不等于对应功能已完成；未接入功能要明确不可用，不得表现为已成功执行。 |
| UI-06 | 整体风格与适配 | 延续已选甜品风格，竖屏、无人物。背景满屏；需求池、盒子、按钮等重要内容避开刘海和底部手势区。 |
| UI-07 | 素材比例 | 甜甜圈、盒子和备货预览等比缩放，避免压扁或拉伸；不同区域同一口味保持一致。 |
| UI-08 | 设置与重开 | 设置入口可打开“重开本关”。若当前无有效搬运且未达到通关条件，页面给出可识别反馈，并保持重开入口可用。 |

20px为设计间距，适配时保持对应设计关系。整页需要同时容纳三个板块，避免关键操作区域被遮挡或相互重叠。

### 3.1 需求池状态

| 状态 | 显示 | 行为 |
| --- | --- | --- |
| 开放、有需求 | 对应甜甜圈口味图标 | 参与需求匹配。 |
| 锁定 | 锁定状态，不显示具体口味 | 不参与当前需求匹配。 |
| 解锁后 | 揭示该位置口味 | 作为开放需求参与匹配。 |
| 对应订单完成且仍有后续 | 更新该位置的后续需求 | 其他未完成的位置保持不变。 |
| 对应位置的序列耗尽 | 显示已完成状态 | 不再参与匹配，也不自动解锁其他位置。 |

### 3.2 操作区状态

| 状态 | 界面表达与交互要求 |
| --- | --- |
| 普通可操作盒 | 可辨认甜甜圈层次及顶部口味，按照取放规则响应操作。 |
| 来源盒已选中 | 有清楚的选中反馈；玩家可以识别当前搬运来源。 |
| 无效目标 | 口味不符、容量不足以放入任何一颗、锁定或该位置无盒时，不执行搬运、不改变盒内数据，反馈原因并保持来源选中。 |
| 隐藏层 | 未露出时不泄露口味；露到顶部时揭示。 |
| 首次归纳完成 | 4颗同味时有短暂完成反馈；后期有带数字机关时可同步展示减数，本期不把它演成打包离场。 |
| 凑齐且等待需求 | 仍占原盒位，可与成功打包状态区分；不播放成功回收反馈，可继续按普通盒规则取放。 |
| 搬空后的空盒 | 保留盒子；不得误显示为已回收或自动补入新盒。 |
| 已回收后的空盒位 | 原盒已离场，等待原位补货；队列耗尽后可保持无盒状态。 |
| 锁定周转盒位 | 占用预留盒位，不能取放；解锁后按普通容量4的盒子显示和操作。 |

“等待需求”在本文中规定的是回收条件，不额外附加新的锁定取放规则。

### 3.3 功能入口状态

三个按钮始终占据底部固定位置，区分可用、不可用和点击反馈。未接入的功能可打开简短说明或显示禁用状态，不扣资源、不改变盒子和需求。正式道具效果、次数、消耗及解锁方式不由按钮图标、参考图或演示代码确定。页面布局应容纳三个入口与出餐预览，避免盒子和甜甜圈被挤压变形。

## 4. 基础玩法与交互规则

### 4.1 F-01 开局出餐

1. 初始化4个需求位置和16个盒位，保持各自初始开放／锁定状态。
2. 从底部出餐区域通过动画，将首批盒子摆入当前可用的常规盒位；两个周转盒位保持锁定。
3. 尚未出场的盒子留在本关有限备货队列中，不额外占用盒位。
4. 开局不另外预留专用补货空位。
5. 开局已装满4颗同味的实体盒标为已归纳状态，入场本身不产生归纳完成事件；如同时匹配开放需求，仍按打包规则自动回收。首期演示关避免开场即回收，让玩家先体验一次整理。
6. 保留本关初始需求、盒位和备货配置，供“重开本关”恢复；重开不继承上一次尝试中的搬运、归纳计数或已补货状态。

例如，本关有25个盒子，先摆入当前可用的盒位，其余通过后续回收补位陆续出场；整关处理数量可超过16盒，但同屏始终不超过16盒。

### 4.2 F-02 点击、成组搬运与自动拆分

1. 玩家先点击来源盒，再点击目标盒，移动来源盒顶部已显示口味的甜甜圈。
2. 普通目标盒必须有空位，且为空盒或顶部为同口味。
3. 来源盒顶部连续同口味的甜甜圈可以成组移动，也可以拆分。
4. 目标容量足够时，整组移入；容量不足时，自动放入可容纳的数量，其余留在来源盒。
5. 目标只剩一个坑位时，默认拆出一颗放入。
6. 取放同时遵守特殊盒自身限制；不满足条件的搬运不能改变盒内内容。
7. 只能选有甜甜圈、可取出的盒子作为来源；点击已选来源盒可取消选择。无效目标保留当前来源选中，不扣次数、不执行归纳或打包。一次有效搬运完成后清除选中状态。

例如，两颗同口味甜甜圈连在一起，目标盒只剩一个坑位，则移入一颗，另一颗留在来源盒。

### 4.3 F-03 明牌与隐藏层

- 一关可以全部明牌，也可以有隐藏层；明牌与隐藏层可在同一关并存。
- 隐藏甜甜圈露到顶部时揭示口味。
- 刚揭示的甜甜圈即使与本次搬运口味一致，也不在同一次操作中继续自动搬走。

### 4.4 F-04 归纳完成、等待需求与打包回收

玩家有效搬运后，若目标实体盒首次由未归纳状态变为4颗同口味甜甜圈，立即计一次“归纳完成”。同一实体盒只计一次；搬出后再次凑齐不重复计。补货入场的是新实体盒，可以在入场后首次归纳时另计。开局或补货时已装满4颗同味的盒子视为已归纳，不能靠反复拆装补领。归纳完成本身不要求当前需求，也不等于成功打包。

只有同时满足以下条件，才自动打包回收：

- 盒内已有4颗同口味甜甜圈。
- 该盒当前可以打包，不受未解除的盒子限制。
- 当前开放的需求位置中存在对应口味需求。

符合条件后整盒打包，从界面顶部弹出回收，完成对应需求。锁定位置的隐藏需求不能提前参与匹配。多个开放需求位置同时显示同一口味时，本版按从左到右的顺序完成其中一个位置；一次回收只完成一盒需求。

已凑齐但未匹配需求的盒子在原位等待，不释放盒位、不补货、不计消除。若是玩家首次归纳成功，后期带数字机关仍须减数；无数字普通冰冻盒保持冻结。等待盒仍可按普通盒规则取放。

### 4.5 F-05 需求更新与自动连续回收

1. 成功打包回收后，对应需求位置更新后续需求；其他未完成的位置保持不变。
2. 检查场上已凑齐且可以打包的盒子；若有多只同时匹配，按操作区从上到下、从左到右的盒位顺序取第一只。
3. 若有盒子匹配新需求，无需再次点击或搬运，自动打包回收。
4. 继续更新该需求并检查后续匹配，直到没有新的匹配盒子。
5. 每次回收分别完成对应需求、计入消除；同一个需求或同一盒回收不得被重复结算。

需求位置的序列耗尽后显示完成状态，不再匹配该位置；锁定位置保持锁定。本版首期演示关的所有必需需求都配置在两个开放位置，因此锁定位置不会让通关条件无法达成。

**必须支持的典型场景：**

需求池当前开放草莓和巧克力；场上已凑齐一盒蓝莓和一盒橙子。草莓所在需求位置的后续顺序为蓝莓、橙子。

| 步骤 | 触发结果 | 需求池变化 |
| --- | --- | --- |
| 初始 | 蓝莓盒和橙子盒原位等待 | 草莓、巧克力仍未完成。 |
| 草莓盒凑齐并匹配需求 | 草莓盒打包回收 | 草莓需求更新为蓝莓。 |
| 新需求匹配已有蓝莓盒 | 蓝莓盒自动打包回收 | 蓝莓需求更新为橙子。 |
| 新需求匹配已有橙子盒 | 橙子盒自动打包回收 | 继续按后续需求检查匹配。 |

巧克力需求始终保持不变。以上连续回收共计3次消除，并计入连单。正式连单机制包含额外金币和钻石奖励，详见第7节；本次不据演示数据确定奖励数值。

### 4.6 F-06 原位出餐补位

- 可补位盒子成功打包回收后，记录其腾出的原盒位；先处理场上已在等待的可打包盒与需求连续更新，再依成功回收的先后顺序，从底部备货队列逐个补入这些原盒位。
- 每次补位只消耗队首的一个备货盒，不移动或重排其他盒子。全部已在场的连续回收处理完毕后，再检查新补入盒子是否已装满且匹配当前需求；如匹配，继续正常回收与补位，直到状态稳定或队列耗尽。
- 搬空盒子不补货；凑齐但等待需求的盒子不补货。
- 单颗暂存盒位不参与补位。周转盒解锁后，补货规则与常规盒相同。
- 备货预览不可操作；队列耗尽即停止补货，不凭空生成新盒子。
- 新补入的盒子不追溯享受入场前发生的归纳完成或回收事件；入场已满同味也不产生新的归纳完成事件。

需求更新、无数字普通冰冻盒解冻、补货来自真实的打包回收事件；带数字机关则来自真实的归纳完成事件。展示动画可以衔接，但不能让同一事件重复补位或重复计数。

### 4.7 F-07 归纳与回收事件的处理顺序

| 事件 | 归纳计数 | 消除计数 | 后期机关结果 |
| --- | --- | --- | --- |
| 玩家首次凑齐4颗同味，当前无对应需求 | 该实体盒计1次 | 0次 | 所有在场带数字盒各减1；无数字普通冰冻盒不解冻。 |
| 玩家首次凑齐4颗同味，且匹配需求并回收 | 该实体盒计1次 | 回收时计1次 | 所有在场带数字盒各减1；回收使一盒无数字普通冰冻盒解冻。 |
| 新需求让此前已归纳的等待盒自动回收 | 0次 | 每回收一盒计1次 | 带数字盒不减数；每次回收可使一盒无数字普通冰冻盒解冻。 |
| 同一实体盒再次凑齐4颗同味 | 0次 | 仅符合需求并实际打包时计1次 | 不因重复归纳减少带数字盒。 |
| 单颗暂存盒装满、盒子开盖或破冰 | 0次 | 0次 | 解锁或暂存动作本身不触发归纳、消除；解锁后的四格盒若随后实际打包，再按打包事件处理。 |

后期机关启用时，一次有效搬运按“更新盒内甜甜圈与隐藏层 → 记录首次归纳完成并使所有在场带数字盒各减1 → 归零开盖或破冰 → 检查匹配需求并依次打包 → 更新对应需求、无数字冰冻盒解冻 → 检查场上所有当前可打包的满盒并连续回收 → 原位补货 → 检查新入场盒 → 判定通关”的顺序处理。每只实体盒最多产生一次归纳完成；同一盒即使在本次搬运中立即打包，也只产生一次归纳与一次消除。自动打包已有满盒、开盖、破冰、搬空或补货入场本身不会补记归纳。

对同时存在多个无数字普通冰冻盒的关卡，本版按操作区从上到下、从左到右的顺序选择一盒解冻；已破冰或带数字的冰冻盒不参与这个单盒选择。该顺序是本版为保证效果可预测而确定的实现约定，不改变“一次成功回收只解冻一盒”的玩法。

### 4.8 F-08 通关

两个开放需求位置中为本关配置的有限序列均完成，并清空本关场内和备货中的所有甜甜圈后通关；空盒和两个锁定位置可以保留。不能仅因当前场上暂时没有甜甜圈，就忽略未完成需求或未出场备货。每轮操作的自动回收与补货都结算稳定后，才检查通关。

若结算稳定后既未通关，又无有效搬运且没有待自动回收的盒子，界面提示本次尝试无法继续，玩家可从设置入口重开本关。重开恢复本关初始盒位、口味、需求与备货，不增加本关奖励，也不占用底部“撤回”的道具次数。

## 5. 动画与反馈要求

| 动作 | 起点与结果 | 验收重点 |
| --- | --- | --- |
| 开局摆盒 | 底部出餐区 → 中部可用盒位 | 有出餐、摆入的动画表现，盒子最终落入正确盒位。 |
| 搬运 | 来源盒顶部 → 目标盒 | 移动口味及数量与规则一致；来源剩余内容清楚可见。 |
| 隐藏层揭示 | 隐藏层露到顶部 → 显示真实口味 | 不提前显示，也不在同一次搬运中额外搬走。 |
| 归纳完成 | 目标盒首次凑齐4颗同味 | 给短暂、清楚的完成反馈；若当前无需求，盒子留在原位。后期带数字机关启用时同步显示在场数字变化。 |
| 成功打包 | 匹配需求的盒子 → 界面顶部回收 | 有整盒打包与离场表现；等待需求的满盒不得使用该反馈。 |
| 需求更新 | 完成的需求位置 → 后续需求 | 更新的是对应位置，未完成的位置保持原状。 |
| 自动连续回收 | 新需求匹配场上已有满盒 | 自动衔接，无需再次点击；每盒分别结算。 |
| 补位 | 底部出餐区 → 刚回收的原盒位 | 不抢占其他盒位，不重排其他盒子。 |
| 无效操作 | 未满足放入或取出条件 | 给出可辨认反馈，原盒、目标盒及备货数据不变。 |
| 数字开盖／破冰（后续） | 归纳完成 → 所有在场数字各减1 | 归零才解除对应限制；单颗冰冻暂存盒解锁后仍只能装1颗。此项不纳入首期可运行验收。 |
| 通关 | 全部需求和甜甜圈处理完毕 | 明确反馈本关完成，不编造尚未确定的奖励。 |

动画期间阻止重复提交来源／目标点击，数据结算与表现按第4.7节顺序保持一致。动画不得让一次有效操作被重复执行，也不得因视觉层与数据不同步导致数量丢失、重复或超过盒子容量。本节规定动作方向与结果，不固定未经确认的动画时长、特效强度或音效方案。

### 7.1 底部置顶盒

此功能由盒子自身自动触发，与底部“置顶”功能入口分开描述；不能据此推定置顶道具的使用规则。

- 只有从带有该功能的来源盒成功搬出甜甜圈才触发；仅放入、选中或搬运失败不触发。
- 先完成本次搬运，再将来源盒剩余甜甜圈中最底部的一颗移到顶部，其余保持相对顺序。
- 无论一次移出一颗还是一组，只触发一次；成组与拆分仍沿用基础规则。
- 新置顶的甜甜圈不在本次操作中继续自动搬出；若为隐藏层，则揭示口味。
- 搬空后无需置顶；仅剩一颗时排列不变。
- 置顶本身不计消除，不直接触发补位、解冻或数字盖盒减数。

例如，来源盒从上到下为“草莓、巧克力、橙子、蓝莓”。成功搬出草莓后，蓝莓置顶，排列变为“蓝莓、巧克力、橙子”，下一次可搬运的是蓝莓。

### 7.2 炸弹计时

- 出现且可操作时开始计时。
- 教学、入场、设置暂停、切后台和系统结算期间暂停。
- 普通移动不刷新时间，重开恢复初始时限。
- 倒计时归零前，系统已接受且满足打包条件的操作，优先判定成功，不因打包动画耗时导致失败。

### 7.3 机关联动边界与设计反馈

首次归纳完成一只实体盒后，在场的所有数字盖盒、数字冰冻盒和数字冰冻单颗暂存盒均减1；两只同口味的盒子也分别有效。满盒等待需求可以减数。重复凑齐同一实体盒、开盖、破冰和单颗暂存盒装满都不能再次减数。初始已经装满同味的盒子不因入场、开盖或破冰产生归纳事件。

无数字普通冰冻盒只受真实打包回收触发，一次回收只解冻一盒；需求更新造成的自动回收同样有效。数字减数、普通冰冻解冻、打包回收在同一步发生时按第4.7节顺序反馈，不能把数字递减动画误画成“盒子已打包”。所有在场带数字盒同时减数；新补入盒子不追溯之前的归纳或回收。

后续设计稿应分别表现未解锁、数字递减、归零开盖或破冰、解锁后可操作的状态。数字冰冻单颗暂存盒保持较小外形；数字冰冻普通盒与常规四格盒保持外接尺寸关系。机制只在配置对应关卡时生效，不作为每局默认流程。

### 7.4 后续机制验收场景（本次不实施）

| 场景 | 预期结果 |
| --- | --- |
| 同一口味的两只不同实体盒先后首次凑齐4颗，场上同时有数字盖盒、数字冰冻盒和数字冰冻单颗暂存盒，数字均为2 | 第一次归纳后三类盒各显示1；第二次归纳后均归零并解锁。两盒口味相同不影响计数，且无须等待打包。 |
| 满盒暂不匹配当前开放需求，随后需求变化而自动回收 | 首次凑满时所有在场带数字盒各减1；自动回收时不再减数，但可使一盒无数字普通冰冻盒解冻。 |
| 同一实体盒先凑满、后搬空、再凑满 | 该实体盒只在第一次凑满时触发归纳完成；第二次凑满不让带数字盒减数，若匹配需求仍可正常打包。 |
| 一盒归纳后打包，补货进入同一盒位 | 原盒归纳和打包各计一次；补货盒属于新实体，不继承原盒的归纳状态。若补货时已是四颗同味，仅标记为已归纳，不补记归纳完成事件。 |
| 数字冰冻单颗暂存盒归零破冰后放入一颗甜甜圈 | 盒子仅能暂存这一颗；装满不打包、不补货，也不使其他带数字盒减数。 |
