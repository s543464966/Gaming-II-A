# 小游戏平台画面比例与安全区

状态：已实现，2026-09-23 完成自动化验证与抖音开发者工具模拟器复测；真机验证待完成。下方验证记录保留当时的成组搬运步数，现行连续同味搬运规则见[基础玩法](basic_gameplay.md)。

## 问题与原因

用户提供的抖音模拟器截图中，甜甜圈、盒子、订单和按钮同时横向变窄。原因位于固定版本 `1.1.27` 的抖音启动器：读取系统信息时把 `screenHeight` 同时赋给了宽度和高度。引擎根据错误尺寸创建正方形画布，随后宿主将其显示在竖屏区域，造成整张画面变形。

以模拟器的 iPhone 15 Pro 为例，逻辑屏幕为 393 × 852、DPR 为 3；错误宽高会导致正方形渲染。正确的全屏画布像素尺寸应为 1179 × 2556，宽高比始终与逻辑窗口一致。

## 已实现的适配行为

| 层次 | 行为与实现位置 |
| --- | --- |
| 抖音启动器 | [导出入口](../Tooling/export/douyin.mjs)在校验上游文件后，对唯一固定锚点修正宽高读取；锚点不匹配时停止构建，避免静默产生错误包。 |
| 宿主画布 | [抖音入口](../Coding/godot/platforms/douyin/runtime/game.js)优先使用逻辑窗口宽高，按 DPR 设置画布像素尺寸；窗口变化和回到前台时重新同步。 |
| 两端安全区 | [宿主接口](../Coding/godot/platforms/minigame/runtime/host_viewport.js)读取安全区、状态栏及胶囊位置；[Godot 适配器](../Coding/godot/platforms/minigame/host_viewport.gd)通过直接接口调用读取数据，兼容禁止动态脚本求值的小游戏环境。 |
| 页面布局 | [关卡页面](../Coding/godot/features/donut_sort/ui/donut_sort_screen.gd)在安全区内等比缩放并居中；背景覆盖全屏，所有玩法控件保持统一缩放。 |
| 输入 | 调整布局时取消未完成拖拽；鼠标和触摸落点继续使用实际页面变换，避免画面与操作区域错位。 |

安全区数据使用宿主逻辑像素，映射到 Godot 视口时不再次乘 DPR。桌面预览及无法提供有效宿主尺寸时沿用完整视口。微信共用安全区接口，但不套用抖音启动器补丁。
