# UI 比例与组合检查

视觉依据：[用户参考稿](../Archive/ReferenceImage/donut_sort_reference.png)。基础画布为 1024×1536，实际素材来自 `donut_game_assets_v1`。

## 比例修正

上一版把参考图的可见外框直接当成素材显示尺寸，导致棋盘餐盒拉高、备货餐盒压扁。将首排尺寸改为 174×169 并不能证明贴合参考；此前围绕这些尺寸的结论和测试已撤销。

目前按原图宽高比显示所有插画和按钮纹理，通过位置、留白和整体等比缩放排版。木板也按自身比例显示，四排盒位位于其内部。餐盒前后层始终共用 `1082×849` 的裁切区域与相同显示矩形；备货复用同一餐盒场景，仅整体缩小并将食物排列为最多两行。没有为备货重新压缩餐盒高度。

甜甜圈在棋盘、订单、备货、拖拽和飞行动画中均等比显示。食物从盒底向上叠放，前沿覆盖下层底部；备货一到两颗时居中放置。数字盖、锁定盒和冰霜按各自原始比例显示。原始 PNG 未修改。

较长竖屏对完整画布统一缩放并居中，额外高度由店铺背景承接。稳定位置保存在 `donut_sort_screen.tscn`，餐盒组合归 `donut_box.tscn` 与 `donut_box.gd`。

## 验证

`node Testing/scripts/run_godot.mjs architecture home donut` 验证结构、三关完整解、数量守恒、点击与拖拽、撤回、暂停和缩放取消。比例回归检查会检测非等比纹理变换、强制拉伸以及棋盘与备货的餐盒几何差异，已确认可以复现上一版问题；不再把上一版错误尺寸作为验收标准。

真实 Godot 4.5.1 Compatibility 渲染检查覆盖 1024×1536、720×1280、720×1600 和三关状态，并通过实际视口输入完成跨排转移、出餐、撤回、暂停及继续。

## 与参考稿的差异

素材包并非参考稿的逐像素拆层：餐盒、按钮和木板自身的宽高比、锁和背景家具均有差异。本轮保留这些原始形状，因此部分区域占位与参考稿不同。若继续追求外形一致，需要对应形状的美术资产，不能再靠非等比拉伸实现。

订单数、口味分布、解锁状态和备货数量来自现有关卡。本轮未修改关卡或玩法数据，未重新导出微信包或进行真机验收。
