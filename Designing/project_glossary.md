# 项目术语

状态：核心术语及本轮确认的特殊盒、连单与道具定义已同步。  
关联文档：[基础玩法](basic_gameplay.md)。项目策划、界面说明和后续实现沟通使用本表统一含义。

## 1. 核心术语

| 术语 | 定义 |
| --- | --- |
| 盒位 | 操作区内固定的位置；盒子回收后，该位置仍保留。 |
| 空盒 | 有盒子、没有甜甜圈；搬空后仍留在原位，可按盒子规则继续使用。 |
| 空盒位 | 原盒子已被回收、当前没有盒子的位置；与可接收甜甜圈的空盒不同。 |
| 来源盒／目标盒 | 本次取出甜甜圈的盒子／本次接收甜甜圈的盒子。搬运对象是甜甜圈。 |
| 凑齐 | 一个盒子内已有 4 颗同口味甜甜圈，不等同于成功打包。 |
| 等待需求 | 已凑齐，但当前开放需求中没有对应口味；盒子继续留在原位。 |
| 打包回收／消除 | 可打包的盒子凑齐且匹配当前开放需求，整盒打包并回收；成功回收 1 盒计 1 次消除。 |
| 备货队列 | 本关尚未出场的有限预设盒子队列，由底部出餐区域依次补入。 |

“等待需求”规定的是回收条件，不额外附加新的锁定取放规则。等待中的盒子是否可取放，仍按普通搬运规则及该盒自身限制判断。

## 2. 需求与结算

| 术语 | 定义 |
| --- | --- |
| 需求位置 | 顶部承载需求的固定位置，可能处于开放或锁定状态；本方案初始化 4 个。 |
| 开放需求 | 当前开放需求位置中显示、可参与打包匹配的需求。 |
| 锁定需求 | 尚未开放的需求位置中的隐藏需求，不能提前参与匹配。 |
| 需求池 | 当前可参与匹配的开放需求集合，不包含锁定位置的隐藏需求。 |
| 后续需求 | 某需求位置当前需求完成后接续出现的需求；只更新完成的位置，其他未完成的位置不变。 |
| 需求匹配 | 可打包且已凑齐的盒子口味与某个开放需求相符，使该盒满足打包回收条件。 |
| 自动连续回收 | 需求更新后，场上已凑齐且可打包的盒子继续自动匹配并回收，直到没有新的匹配盒子；不要求玩家再次点击或搬运。 |
| 消除次数 | 成功打包回收的盒数；每盒各计 1 次，不按甜甜圈颗数、动画次数或机关变化次数计算。 |
| 连单 | 同一次玩家操作及其自动结算引发的连续回收；跨操作不累计。按该次实际回收数结算最高奖励档位，数值见基础玩法第 7 节。 |
| 本关奖励 | 本关操作结算得到的金币与钻石；撤回同步恢复，重开／切关清零，尚非跨关账号资产。 |
| 通关 | 本关全部需求完成，且场上与备货中的所有甜甜圈均已处理完；空盒可以保留。 |

## 3. 搬运与可见性

| 术语 | 定义 |
| --- | --- |
| 顶部 | 盒内当前可首先取出的甜甜圈所在位置。 |
| 连续同口味组 | 来源盒顶部连续、口味已显示且相同的一组甜甜圈，是一次成组搬运的候选范围。 |
| 拖拽搬运 | 按住来源盒的甜甜圈并拖到目标盒松手；跟手显示只是预览，合法落点才提交一次搬运。 |
| 成组搬运 | 同一次操作搬运顶部已显示的连续同味组；实际数量受目标剩余容量及盒子自身规则限制。 |
| 自动拆分 | 目标容量不足时，仅移入目标可容纳的数量，其余留在来源盒。 |
| 坑位／剩余容量 | 盒内还能容纳甜甜圈的数量；属于盒内空间，不是操作区中的盒位。 |
| 搬空 | 通过搬运取走盒内全部甜甜圈；结果为空盒，不是打包回收。 |
| 明牌 | 甜甜圈口味已显示的状态。 |
| 隐藏层 | 盒内尚未显示口味的甜甜圈层；露到顶部时揭示。 |
| 揭示 | 隐藏甜甜圈露到顶部后显示口味；刚揭示的甜甜圈不追加到本次搬运。 |

## 4. 盒子类别与机关

| 术语 | 定义 |
| --- | --- |
| 常规盒／常规盒位 | 按普通规则使用的餐盒／用于摆放常规盒的固定位置。可补位的盒子回收后，由备货队列原位补入整盒。 |
| 周转盒／周转盒位 | 提供周转空间的餐盒／对应盒位；两个盒位开局锁定，由加餐盒依次启用空盒，不消耗备货。解锁后补货规则与常规盒相同；搬空保留空盒，成功打包才回收。 |
| 单颗暂存盒位 | 用于暂存单颗甜甜圈的位置，不参与备货补位；装满本身不计消除、不触发机关。占用固定 16 格之一，容量为 1。 |
| 特殊盒 | 附带额外取放或打包限制的盒子；普通搬运与回收条件之外，还须满足其自身规则。 |
| 可打包 | 盒子当前不受未解除的打包限制；仍须同时凑齐并匹配开放需求，才会实际回收。 |
| 数字盖盒 | 带数字盖机关的盒子；机关启用后，每次真实消除使当前在场的各数字盖盒各减 1。归零开盖；未开盖时禁止取放、置顶和打包。 |
| 冰冻盒 | 带冰冻限制的盒子；机关启用后，每次真实消除从当前在场的冰冻盒中解冻 1 盒。按盒位顺序选择；未解冻时禁止取放、置顶和打包。 |
| 开盖／解冻（破冰） | 解除对应盒子限制的状态变化；这些变化本身不等于回收，不计消除，也不单独触发补货或机关计数。 |

## 5. 出餐与补位

| 术语 | 定义 |
| --- | --- |
| 底部出餐区域 | 首批盒子和后续备货盒进入操作区的动画来源区域；成功打包盒的回收方向为界面顶部。 |
| 开局出餐 | 将首批盒子从底部出餐区域摆入当前可用常规盒位的过程。 |
| 原位出餐补位／补货 | 可补位盒子成功打包回收后，从备货队首取 1 个整盒，补入刚腾出的原盒位；不重排其他盒子。 |
| 队首备货盒 | 备货队列中下一个等待入场的预设整盒；每次补位只消耗对应的 1 盒。 |
| 备货预览 | 对尚未出场备货的显示，不可用于取放或直接操作。 |

## 6. 使用边界

- 描述数量时区分盒位数量、盒子数量、甜甜圈颗数和消除次数。同屏最多 16 盒，不代表整关最多处理 16 盒。
- 空盒可按自身规则接收甜甜圈；空盒位没有容器，不能当作空盒使用。
- “凑齐”“等待需求”“打包回收”分别表示不同阶段，不能互换。
- 搬空、暂存盒装满、开盖或破冰本身均不计消除；一次真实回收只结算一次。
- 当前实现使用“周转盒”与“备货”；旧参考图中的“临时餐盒”“待补”以本版规则和数量单位为准。
