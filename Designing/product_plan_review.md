# 策划信息取舍与规则核对

核对日期：2026-09-30。本文记录本次正文整理的依据、信息分类和规则去向，便于检查遗漏；规则正文仍维护在[产品策划方案](product_plan.md)，本记录不另建一套玩法要求。

## 核对依据

逐段阅读迁入前的原始《产品策划方案》全部九章，对照[局内需求 V1.3](requirements/in_game_v1_3.md)、[已确认局内调整](v1_3_alignment.md)、[R2 百关接入](r2_level_update.md)及[早期基础玩法](basic_gameplay.md)中的明确确认记录。原稿来源与迁入摘要保留在[迁入清单](planning_import_manifest.json)。

原稿用于追查遗漏，后续明确确认的修改用于处理旧规则。当前实现只用于核实已实现状态，不单凭代码替代设计决定。不同来源仍有冲突时标出范围与待定项，不以“精简”“总纲”或“以后写产品文档”为由选择性删除。

## 信息重要性的判断

| 信息类别 | 判断标准 | 本次处理 |
| --- | --- | --- |
| 必须保留的产品信息 | 决定做什么、核心乐趣、系统作用、阶段范围 | 正文保留，并与玩法规则连接 |
| 必须保留的玩法约束 | 改动后会改变合法操作、信息可见性、触发对象、次数、顺序、胜负、奖励或资源 | 正文完整表达，不只留机制名称或设计目的 |
| 专项明细 | 素材逐项配料、未定金额试算、测试执行命令、配置与接口实现 | 保存于配套资料并给出入口，不冒充正式规则，不当作无价值资料删除 |
| 可合并的重复内容 | 同一规则反复解释，多个例子表达同一结果 | 保留明确规则与有助于理解的代表例子，去掉重复段落 |
| 过时或过程性内容 | 已被确认修改的旧布局、旧进度、迁移过程、临时制作说明 | 正文使用现行状态，历史证据留原记录，不恢复旧规则 |

例如，“每次只选一只数字盒减一”虽具体，却直接决定玩法，必须留在正文；脚本命令虽然有工作价值，却不影响玩家规则，可以留在验收资料。重要性不能按句子长短或技术词多少判断。

## 已存在的版本差异

这些差异在本轮核对前就已存在。本轮恢复约束不意味着把原稿所有旧条款原样覆盖现行版本。

| 主题 | 原稿或历史表述 | 采用与保留方式 |
| --- | --- | --- |
| 预设布局 | 自由散点、围合和中央留白 | 用户后续要求连续紧凑、最多五盒每排、对称留白；采用 R2 及当前工作区规则 |
| 备货表现 | 底部出餐与备货预览 | 按已确认局内调整保留有限队列，取消预览，左右入场 |
| 炸弹解除 | 必须匹配订单并回收 | 按已确认修订采用首次四同味归纳即解除；原回收口径保留历史需求，不恢复到正文 |
| 道具 | 均由广告取得、效果待定 | 后续确认每关三种各一次，保留明确效果；额外广告补次仍待定 |
| 素材状态 | 六种现有、九种拟新增 | 已有十五种资源与贴纸；原配料意图仍保存，不假定现图逐项满足原意图 |
| 制作进度 | 百关还需制作求解 | R2 已有首轮内容与正式回放，真人与平台验证仍未全部完成 |
| 连单范围 | 原产品稿经济试算为跨操作八秒；早期已确认玩法和当前游戏为同次操作 | 本轮不改当前游戏计数，也不再把八秒试算宣告删除；两种范围在经济说明中并列标明，未来正式跨关奖励采用哪一套须明确决定 |
