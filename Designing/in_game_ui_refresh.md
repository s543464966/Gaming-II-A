> 历史实施记录：其中固定 17 盒、早期关卡数值与原屏幕比例已由 2026-09-29 的[前十关盒位调整](board_layouts.md)替代，不作为当前产品规则。

当前布局已继续更新为独立配置的交错、对齐、围合与散点构图；标题间隔、贴纸、柜体留白和特殊状态的最新实现见 [局内盒位布局优化](board_layouts.md)。下文保留本日此前的素材与适配过程。

2026-09-29，接入用户提供的 `donut_game_assets_v8`。这次修改覆盖真实游戏页面，保留十关、17 个盒位、两开两锁订单、道具次数、隐藏层、冰冻与数字盖。素材包中的四列示意和未实现功能说明不作为关卡规则。

## 素材判断与替换

| 部位 | 本次处理 | 原因 |

| 锁定订单 | 完整盒体实时去色，叠加锁图标 | 两个未开放位置不会透露下一种口味；不改原 PNG |
| 棋盘容器 | 完整浅粉圆纸托替换方纸盒后层与前沿 | 新图没有独立遮挡前沿，不能继续用旧前沿遮住食物 |
| 常规食物 | 六张纯色图替换对应旧图，同日增补的奶白香草替换临时沿用的旧图 | 用户确认先更新香草与贴纸，保留现有十关、七种口味 |
| 标题、设置、三个道具 | 复用原资源，只调整整体分层和底部位置 | 与新包的七张基础 UI 逐文件比对完全一致，无需新增重复图 |
| 隐藏、冰冻、数字盖、打包及失败弹窗 | 继续使用原图 | 新包未提供替换图，现有关卡仍依赖这些可见状态 |

首轮导入 16 张原始 PNG，同日增补 24 张，SHA-256 均与各批包清单一致。所有 `.tres` 只裁去透明留白，不重画或压扁图片。原有美术全部保留。新原图分别归食物、订单、棋盘与页面背景的 Owner，哈希记录在各自 `asset_manifest.json`。素材包的预览 HTML、制作脚本及源路径未复制到运行工程。

口味 ID 仍为 0～6，当前视觉依次为粉、棕、绿、蓝、橙、香草、紫；原柠檬位 ID 4 仅切换为橙色图。香草订单用去色并着奶油色的现有盒底，盒盖显示配对的奶白贴纸。未增加第八种关卡口味或合并现有关卡口味。

## 组合与适配

- 页面以 1024 为设计宽度，在设备安全区等比缩放。标题和设置保持原有可点击入口。
- 四个翻盖盒每个为 222×256 的布局区，台面遮住底部少量区域；口味图、锁和完成标记均在遮挡线以上。不重复显示固定容量 `×4`。
- 背景先画墙面和地板，再画订单，再画台面，最后画棋盘。短屏裁掉中段上部的空台面，长屏等比覆盖并裁掉两侧；柜体、木纹及窗口保持原始宽高比。墙面从上端裁切，避免截掉黑板顶部。
- 棋盘仍为 5／5／5／2，纸托布局区 200×126，甜甜圈显示区 176×126，固定层距 48。小屏按可用桌面整体缩放，所有盒位保持相同尺寸。真实空纸托与无容器的空位置保持区分。
- 入场、补位、拖拽与逐颗飞行动效共享新纸托与食物坐标。普通纸托没有前景遮挡层，原数字盖仍独立覆盖。
- 道具保留真实次数与点击反馈，位于底部地板；置顶选择、完成反馈和取消逻辑继续使用原模块。

## 手机上下留白修复

用户的 iPhone 16 Pro Max 截图来自抖音小游戏，截图仍为旧版方纸盒素材。代码中原有的长屏适配会随剩余高度增加标题与订单之间的留白，并把台面高度限制为背景图片按宽度缩放后的高度，额外空间因而堆在头部和地板上。

首轮收紧时先读取宿主实际窗口、安全区与胶囊位置，再分配页面：头部为 364 设计单位，底部道具区为 248 设计单位，其余交给餐台。系统安全区单独避让，不按机型名称或截图写死。中段背景使用相同的等比覆盖系数计算柜体边界，保证棋盘留在台面上。纸托缩放上限从 0.84 调整为 0.92，行距限制在 18～40 设计单位；四排各自预留四颗容量，移动食物不会造成布局跳动。此轮网页缺少额外基础边距，后续已按下节再次平衡。

使用截图的 1320×2868 比例，按 440×956 逻辑视口模拟，注入测试安全区与胶囊数据。下表是同一组模拟数据下 v8 素材初版与修复后的引擎测量，不是真机 API 回传值：

| 测量项（逻辑像素） | 修复前 | 修复后 |
| --- | ---: | ---: |
| 标题布局底边至订单布局顶边 | 34.65 | 6.88 |
| 真实纸托可见宽度 | 61.22 | 71.28 |
| 道具底边至可用安全区底边 | 16.97 | 12.68 |
| 地板起点至道具顶边 | 19.69 | 14.54 |

360×960 极长屏中，地板起点至道具的空隙从 123.03 缩至 12.07 逻辑像素；360×640 小屏的真实纸托宽度从 40.05 增至 44.30。截图只呈现游戏渲染，不绘制抖音胶囊或系统状态栏。

## 内边距再平衡（此前版本）

用户在网页预览发现界面贴边。根因是首轮只避让小游戏安全区，普通浏览器没有宿主数据时直接使用完整画布，标题仅离画布上沿约 8 个逻辑像素。现在系统安全区和界面内边距分别计算：可用高度 560～760 逻辑像素之间，额外纵向边距从 16 平滑增至 24；左右基础边距为窗口宽度的 4.5%，限制在 16～24。短屏限制设计舞台宽高比为 1:1.90，为四排食物留出高度；宽屏居中。头部调整为 380 设计单位，标题与订单间隔为 32，底部仍为 248；图片不拉伸。

设置／选关与失败弹窗独立按安全区等比适配、四周至少留 16 逻辑像素，遮罩始终全屏，不跟随棋盘舞台的收窄比例；小屏选关按钮不再被连带缩小。仍使用原输入与生命周期流程。

| 模拟视口 | 标题上方内边距 | 道具下方内边距 | 纸托可见宽度 |
| --- | ---: | ---: | ---: |

单位均为逻辑像素；内边距从安全区可用边缘计算，不含刘海、胶囊和手势区。测试数据用于覆盖布局，未声称采集自手机。`architecture home donut` 全部通过，包含无宿主网页、DPR 1／3、十关完整解、拖拽、弹窗及生命周期；真实 Compatibility 渲染检查十种视口与小屏选关面板。网页和小游戏使用同一套界面边距计算。
