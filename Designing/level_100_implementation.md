# 前 100 关首轮实现与验收

> 本文保留 V1.2 首轮记录，现行数值以 [R2 百关接入](r2_level_update.md) 为准，界面与机制规则沿用 [V1.3 更新](v1_3_alignment.md) 中的后续修订。

2026-09-30 更新。状态：100 关可玩版本已实现；最新反馈将全部关卡统一为上下留白对称且大于可见排间隙，订单贴纸再次缩小。上一轮隐藏圈尺寸、数字机关文案和炸弹长短时限修正保留。难度、首试通过率和真人操作时长仍需试玩调校。本次未提交或推送 Git，也未上传平台包。

## 范围与数据

沿用用户当前 UI、前十关配置和连续居中的布局要求，补齐第 11–100 关。首页、店铺装修和底部出餐区不在本轮范围。“只进不出”规则已实现，但按用户要求不新增其图标；首次提示说明具体盒位，误操作时显示反馈。

运行事实源为 `Coding/godot/game_content/donuts/levels/` 和 `layouts/board_layouts.json`。`level_plan.json` 记录用户数值表“关卡总表”第 6–105 行的只读提取值、来源及 SHA-256，用于核对配置；没有改写用户 Excel。每关按表核对口味、非空盒、普通空盒、单格盒、备货、订单、隐藏比例及主副机制，额外保留两个锁定周转位。隐藏比例按整数颗数取整。当前最多 22 个盒位、10 种同时使用的口味，素材映射支持 15 种。

`Tooling/data/build_hundred_levels.py` 是离线候选生成、求解及夹具制作工具；运行时不依赖 Python、策划表或测试脚本。生成器保留已有关卡文件，不覆盖人工调整。后续修改关卡需同步更新可行解并重跑正式规则回放，不能只修改策划快照后宣称运行内容已更新。

## 已实现行为

| 首次关卡 | 内容 |
| --- | --- |
| 6 | 隐藏层露顶揭示，单次搬运不跨未知层继续取牌 |
| 9 | 有限备货，场内连续结算完成后按稳定盒位顺序原位补入 |
| 21 | 数字盖，首次组成四颗同味推进当前顺序目标一次 |
| 31 | 普通冰冻，每次真实回收只解冻当前顺序的一盒 |
| 41 | 单颗暂存盒，容量为一，不参与整盒订单回收 |
| 51 | 数字冰冻，按组推进，与普通冰冻分别处理 |
| 61 | 固定口味，清空后仍只接收指定口味 |
| 71 | 只进不出，禁止取出及置顶，保留正常整盒回收 |
| 81 | 循环盒，每次搬出后剩余顶层轮转，再揭示新顶层 |
| 91 | 炸弹倒计时，必须整盒收走；搬空不解除，撤回不返还时间 |

初始或补入的同味满盒不会伪造一次“首次成组”。数字机关只推进一个目标，不会同时扣所有盖；普通冰冻不会因成组提前融化。没有普通搬运路线时保留补救入口，不直接判失败。

炸弹在设置、教学、后台及系统自动演出期间暂停；普通搬运动画计时。第 91–100 关初始时限依次为 **120／75／50／165／140／125／135／170／120／95 秒**，包含三关短时限与七关长时限。按四种周转条件下“炸弹整盒真正收走”的步骤数，每步预留 3 秒并至少额外预留 8 秒；不能以搬空或其他订单清完代替解除炸弹。修复了空炸弹留场却被提前判通关的边界，十关验证路径已重新求解。配置保留 `provisional_playtest_required` 标记，这不是真人操作时间测量。

选关面板共 10 页，每页 10 关；首次机制提示可在设置中重看。App 持有进度服务，使用独立 `user://sweet_sort_100_v1.json`，保存当前局、已读提示、完成记录和最近一步撤回，不迁移旧账号。修改关卡内容后旧局存档会校验内容摘要，失效时重新开局。

两个周转位支持分别解锁、取消、同次回调幂等及重开重置。本地预览明确显示模拟观看流程；微信、抖音真实激励广告尚未接入，不能把本地模拟算作平台广告验收。

布局按关卡实际盒数创建，开局上下可见留白对称，回收后保持原位置，已收走盒位不画占位痕迹。21–22 个盒位继续采用四行、每行最多六个连续盒位。先按每排满四层、选中抬起和机关下沿的预留边界收紧多余层距，再计算开局可见排间隙；每侧留白至少为最大空隙的 1.05 倍加 4 个随盒缩放的单位，高度富余时按 1.20 倍约束伸展。基础预留仍不少于每侧 80 设计单位，页面不再重复叠加上下 20 单位内缩。缩放和位置只依赖开局定义及视口，局内食物变化不重新居中。

隐藏圈改用补充包内与普通甜甜圈匹配的 V9 灰圈，保留旧原图；仍用统一 160×114 显示框和等比适配。订单口味贴纸由上一版 74×74 再缩至 64×64（边长约缩小 14%），中心不变。数字机关保留必要计数，移除额外的“下一目标”文字。

## 实际验证

```sh
node Testing/scripts/run_godot.mjs architecture home donut hundred
node Tooling/export/web.mjs
```

百关分别在“双锁、仅 A 开放、仅 B 开放、双开”条件下使用真实 `DonutSession` 完整回放，共 400 条完成路径；检查数量守恒、容量、数值表字段及机制边界。炸弹关每次操作前真实推进三秒，要求在截止前回收炸弹，并在通关时确认没有任何炸弹留场。额外覆盖奖励取消与重复回调、炸弹失败与撤回、存档往返和损坏拒绝、教学暂停、选关末页及焦点恢复。

原有鼠标／触摸、拖拽、撤回、页面生命周期回归通过。100 关在 12 组视口／安全区参数中检查盒位数量、上下留白、四层边界及点击范围；Compatibility 渲染复查机制首关、高密度关卡、小屏菜单和教学弹窗。参考图见 `Archive/ReferenceImage/donut_hundred_*.png`。

网页导出先在隔离项目导入，再验证实际 PCK 中的 100 关、15 组口味／贴纸和代表性页面资源，成功后覆盖唯一 `Archive/Builds/web/`。固定预览为 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)，`build_info.json` 记录该包关卡数量及配置摘要。

## 仍需后续验收

- 可行解证明这些局面存在通关路径，不证明最短解、隐藏信息下的新手公平性或目标首试通过率；解锁后的四条路径也不代表已验证广告收益曲线。
- 炸弹时限、后期难度曲线和颜色辨识需要真人连续试玩。当前 11–100 关为数值约束内的首轮可玩编排。
- 本轮仅完成本地原生／网页验证，没有微信、抖音 IDE 或手机真机验收；真实广告 SDK 未接入。
- 尚无音效与背景音乐；底部备货预览／出餐、首页和装修继续暂缓。
