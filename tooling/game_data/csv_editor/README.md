# CSV 数据编辑器

使用项目固定版本 Godot 打开 `Coding/godot/project.godot`，点击顶部 **CSV 数据** 标签。已打开的旧编辑器需要重新打开工程；也可在「项目 → 项目设置 → 插件」确认 **MagicA CSV Editor** 已启用。

## 使用

- 左侧按 `Archive/GameDesignData/` 实际目录列出 CSV；点击文件后，表头、列和记录全部来自该文件。
- 双击单行单元格直接编辑；选中单元格后，右侧可编辑完整的多行文本或 JSON。所有值均为字符串，不自动转换数字、补值、生成 ID 或解释游戏规则。
- 支持搜索、点击表头排序、分页、调节当前列宽、新增／复制／删除行和按表撤销／重做。排序只影响显示，保存保持原始记录顺序。
- 「保存」保存当前 CSV；「保存全部」保存所有已修改表，再统一同步一次。标签内 `⌘/Ctrl+S`、`⌘/Ctrl+Shift+S` 分别对应这两个动作。
- 文件后的 `*` 表示未保存，`!` 表示外部冲突。切换文件不会丢失编辑。退出编辑器前确认保存结果；Godot 退出项目会提示未保存文件。

CSV 文件数量、分类名称或层级、列数、列顺序都不写死。外部新增、删除、移动 CSV 或调整表头后，点击「刷新」，或返回本标签／重新聚焦编辑器，即按实际文件重建。未保存的外部冲突不会被刷新覆盖，保存会停止；复制需要保留的内容后，用「重新载入当前表」明确放弃本地修改再读盘。

支持 UTF-8（有／无 BOM）、逗号分隔、转义引号、字段内换行、LF／CRLF／CR、空字符串和前导零。要求存在表头且各记录列数一致；损坏格式明确报错，不猜测修补。当前 UI 编辑记录，不提供文件创建、移动或表头增删功能；这些结构操作仍在磁盘文件中进行。

## 保存与游戏同步是两个结果

每份 CSV 先写同目录临时文件、核对指纹，再原位替换。文件外部变更或写入失败时不覆盖原文件。保存全部是逐文件保存：若其中有文件失败，会保留其他已成功保存的文件，提示未完成项，并暂不启动同步。

CSV 保存成功后，连接层异步运行工作区唯一入口 `Tooling/data/data.mjs`，继续使用已有的 `preview → sync → validate`。插件不调用游戏 Schema，也不复制数据构造、校验或发布逻辑。

- 同步成功：游戏生成数据更新。正在运行的普通游戏需重启；已经启动的工作区监听预览会因生成文件变化而重启。
- 同步失败：**CSV 仍已保存**，错误在底部「同步日志」查看。修正后保存，或点击「重新同步」重试。重新同步只读取磁盘，不包含尚未保存的内容。
- 新表、新字段可以被编辑器读取和保存，但要被游戏使用，仍需现有游戏数据管线支持；编辑器的动态展示不等于游戏自动接受任意结构。

需要工作区外层 `Archive`、`Tooling` 与 Node.js。独立产品仓库可以运行现有游戏快照，但没有外层文件时本编辑器不能制作数据。Node 可自动从常见路径与 PATH 查找；必要时在编辑器设置指定 `magica/csv_editor/node_executable`。不会下载依赖、打开游戏、上传或打包。

## 实现边界

`csv_document.gd` 只维护通用 CSV 文本、历史与保存；`csv_panel.tscn/.gd` 只维护显示和交互；`editor_plugin.gd` 负责编辑器注册、来源目录与命令进程连接。Godot 要求的薄入口在 `addons/magica_csv_editor/`。这两处均由现有导出预设排除，游戏运行时不依赖它们。

工作区定向验证：`node Testing/scripts/run_godot.mjs csv-editor csv-sync content tool-entrypoints`。测试只在 `Testing/.runtime/` 的副本上修改数据，不触碰正式策划 CSV。
