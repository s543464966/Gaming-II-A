# UI 输入与生命周期

新增或修改页面的滚动、点击、拖拽、弹窗关闭时，先按下面的职责接入现有组件。稳定布局和视觉仍由场景、Theme 与令牌拥有；输入组件不读取账号或提交玩法事务。

## 滚动与按钮

- 第一方纵向、横向滚动区域使用 `components/touch_scroll_container.gd`，动态正文通过 `UI.scroll()` 创建。组件沿用引擎滚动与惯性，统一拖动阈值，并管理动态后代的输入传播；嵌套滚动由最近的容器负责。引擎 `PopupMenu` 内部节点不属于第一方场景结构。
- 普通动作使用 `button.tscn` / `UI.button()`，图标动作使用 `icon_button.tscn`。需要完全自定义外观的 `Button` 继承或挂载 `touch_button.gd`；它只补充取消事件语义，不覆盖美术。列表中已有原生按钮由滚动组件接入同一取消保护。`OptionButton` 保留引擎下拉菜单行为，不套用普通按钮脚本。
- 滚动区内的可点击条目不能在按下时 `accept_event()` 或抢先提交业务；轻点松开才点击，超过阈值交给滚动。`canceled` 是撤销，不能当作正常松手。重写公共按钮的 `_gui_input()` 时先调用基类。
- 只有确实需要独占手势的控件或子树才设置 `preserve_touch_scroll_filter`。固定页签可调用 `set_touch_scrolling_enabled(false)`；不能通过关闭整页输入或加透明遮罩解决冲突。

## 自定义拖拽

骰子和棋盘保留各自命中几何、拖动表现及业务信号，不建立全局拖拽单例。每次手势只由一个指针拥有；纯触摸和模拟鼠标不能重复开始或结束同一次操作。

命中区域必须随实际显示尺寸和变换计算。取消事件、暂停、应用失焦、隐藏、离树、停用交互都要调用组件自己的撤销入口，清空指针、悬停目标和局部计时，恢复已提交状态。撤销不得消耗奖励、移动单位或打开详情；迟到的松手无效，下一次按下可以重新开始。暂停恢复逻辑不能只写在暂停后不再执行的 `_process()` 中。

## 关闭与重建

输入回调中关闭面板使用 `UI.dismiss(control)`：立即隐藏、停止处理，帧末释放。业务 Owner 同时清空自己的引用、恢复暂停或下层面板。不要在事件仍传播时同步 `remove_child()` / `free()` 当前输入节点；触摸及其模拟鼠标可能仍持有它。

`UI.clear()` 用于普通内容重建，不承担弹窗关闭。如果动作会重建触发它的条目，应在当前输入结束后执行重建，并校验条目身份和宿主仍有效，避免迟到回调提交旧操作。页面切换继续走 App 现有延迟导航。

## 验证

工作区根运行 `node Testing/scripts/run_godot.mjs touch-scroll scroll-pages`。前者验证公共组件的动态接管、嵌套边界、取消与下一次点击；后者检查所有第一方场景的滚动与按钮接入，并向真实页面派发触摸，验证正文和条目起手、详情关闭及缓存页面返回后的实际偏移。

修改自定义拖拽时补跑其业务回归：`adventure-scene`、`reward-dice-tray`；奖励卡和响应式布局由 `mobile-layout` 覆盖。断言必须验证实际滚动、业务信号或消耗，不能仅判断变量已清空。公共生命周期修改还需运行 `architecture home platform`。所有数据使用 Testing 的隔离会话；模拟器和真机结果分别报告。
