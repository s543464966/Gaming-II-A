# 甜甜圈排序结构

`donut_session.gd` 是关卡实例的唯一状态入口。玩家操作在这里原子提交，连续回收按盒位顺序结算，并产生带快照的事件；撤回恢复整个操作。`donut_level.gd` 只加载和校验 `game_content/donuts/levels/` 中的静态定义。

每个功能目录同时维护规则与该功能专用的 `ui/` 场景和脚本：

| 目录 | 职责 |
| --- | --- |
| `board/` | 连续同味搬运、容量和盒位规则；棋盘、圆纸托、手势界面及保留的 v7 机关包装。 |
| `donuts/` | 甜甜圈素材入口与盒内堆叠界面。 |
| `orders/` | 需求、匹配及显式解锁规则；四个翻盖盒默认左二接单、右二去色锁定，不单独显示关卡订单数量。 |
| `currency/` | 暂时隐藏的本关金币只读视图；保留模块与素材，金额来自会话快照。 |
| `settings/` | 齿轮入口及设置面板；百关分页选择（每页十关）、重开、返回、玩法回看与宿主侧边栏入口。 |
| `learning/` | 当前机制的首次提示、图示和统一确认弹窗；是否已读由 App 注入的进度服务持有。 |
| `completion/` | 餐台底部完成反馈与末关重玩入口；页面协调自动切关及生命周期。 |
| `failure/` | 失败弹窗、标题与插画素材、Home／Try Again 图片按钮；只转发导航和重试意图。 |
| `dispatch/` | 同味整盒打包匹配。会话负责回收、机关和原位补货的执行顺序。 |
| `presentation/` | 跨模块的已提交事件时间线与临时飞行动效；首批与补位餐盒按目标所在半区，从左右可见边界外等比水平移入；备货队列不在界面展示。 |
| `tools/undo/` | 完整快照历史及撤回按钮。 |
| `tools/add_box/` | 固定周转盒位的选择、通关归还额外空盒的规则及加餐盒按钮。 |
| `tools/top/` | 下层置顶规则、按钮和底部内嵌选择界面；已知层显色，未知层可盲选。 |
| `tools/ui/` | 组合三个道具按钮、转发操作意图，并维护共用按钮底板和次数角标。 |

根 `ui/donut_sort_screen.tscn` 是页面唯一装配点，只摆放各模块的根场景及页面公共控件，不维护模块内部的金币、设置、盒位、订单卡或道具按钮布局。`ui/donut_sort_screen.gd` 连接模块与会话并处理页面生命周期；`ui/donut_background.tscn` 组合完整的店铺与木台背景，`ui/art/` 保存页面专属素材。UI 不保存第二份玩法状态。

`orders/` 维护初始开放状态，默认只开放左侧两位。右侧两位当前没有订单序列，不参与匹配或阻塞通关。会话预留 `unlock_order_slot(index)`，只负责开放状态、后续匹配、事件与完整撤回；目前没有玩家调用入口，解锁条件、费用与解锁后订单编排留待确定，重开恢复关卡初始状态。

失败由会话 `is_failed()` 派生，目前由未解除炸弹超时触发。炸弹盒首次凑齐四颗同味即转为普通盒，标识与倒计时消失；没有对应订单时留在原位等待，单纯搬空不解除，撤回归纳会恢复原炸弹与原截止时间。无可移动位置时保留补救入口，不直接判失败；停滞时轻提示周转盒。炸弹设置、教学、后台及系统演出期间暂停，普通搬运动画计时，撤回不返还时间。遮罩阻止棋盘与道具操作，返回键不关闭失败弹窗。Try Again 重开当前关卡并重置奖励与道具；Home 只发出页面的 `home_requested` 信号，保留面板和重试入口，等待后续主页导航接入。

`orders/ui/donut_orders_view.tscn` 以固定间距组合四个独立翻盖盒；`donut_order_card.tscn` 将专用正俯视口味贴纸放在盒盖中。甜甜圈、锁及完成勾号共用 `LidContent` 中心 (110, 83)，对应原图波浪背景贴纸的可见中心，文字最小尺寸变化也向两侧扩展，避免偏移。锁定位用 Shader 完整去色，完成后显示勾号。台面在订单盒前方微遮盒底，不遮口味或状态；`STICKER_ART` 与棋盘十五种口味 ID 对应，场内继续使用独立的立体食物纹理。

失败弹窗在安全区居中，宽度不超过安全区的 80%／360 逻辑像素，高度不超过 58%；保留图片等比缩放和原按钮交互。设置、教学和确认弹窗沿用各自既有尺寸，不受该限制影响。

`board/ui/donut_box.tscn` 组合圆纸托、甜甜圈和机关，纸托设计区 200×126。棋盘按 `game_content/donuts/layouts/board_layouts.json` 创建实际数量的盒位，前十关为 6～9 个；所有关卡按最多五盒一排均摊余数，优先四至五盒，16～20 盒时使用四排；布局等比缩放，最大系数 1.08。先按满四层抬起及机关下沿压缩排间多余预留，保持行数、横坐标和索引，再按开局整排边界计算对称留白。每侧至少为最大可见排间隙的 1.05 倍加 4 个随盒缩放的单位，高度富余时按 1.20 倍限制行距伸展；基础上下预留共 160 设计单位，页面不再重复增加内缩。缩放与坐标不随局内食物数量改变。订单贴纸为居中的 64×64；灰色隐藏圈与普通口味采用匹配比例的素材，数字机关仅保留必要计数。动态创建的盒位由棋盘统一转发按压事件，输入路由持有同一数组引用。标题贴近安全区顶部，墙面保留窗下绿植，柜体下边框完整显示；底部三个道具每关各 1 次，首批与补货从左右两侧进入固定盒位。配置与截图见 [盒位布局](../../../../Designing/board_layouts.md)。

三个道具各自在 `tools/<功能>/ui/` 维护按钮场景与专用图标；`tools/ui/art/` 保存道具共用的粉色次数角标与浅色按钮裁切资源。原始浅色按钮底板由 `design_system/art/` 共用，设置按钮也使用这份素材。`tools/ui/donut_tools_view.tscn` 负责三个按钮的居中并排布局，页面只放置道具模块根节点。

规则查询和界面显示都从会话快照取得数据。新增回收事件时，同时检查连续结算、撤回、动效中断和全部关卡完整解。工作区测试入口为 `node Testing/scripts/run_godot.mjs architecture home donut hundred`。百关机制、V9 素材、存档及模拟广告范围见 [实现与验收](../../../../Designing/level_100_implementation.md)。

关卡的容器预算按“初始实际盒数＋备货盒数−订单数”核对，不再强制为 2～3。通关后 `spare_return` 事件归还道具增加的等量空容器，不计订单或奖励；和最后一步一起撤回。快照的 `won` 是通关条件的派生值，棋盘据此隐藏未启用的周转入口，恢复未通关快照时重新显示。

首次遇到机制时显示一次提示，可在设置回看；切关、重开及周转奖励使用明确确认。置顶选项仍暂时替换底部道具区，可切换餐盒或取消，取消与生命周期中断不扣次数。通关后 `completion/` 显示约 1.2 秒完成反馈，页面自动进入下一关；设置打开、隐藏、失焦或外部暂停会停住切关，恢复后重新计时，旧导航不会重复执行。第 100 关保持完成餐台并提供重玩按钮。失败与玩家主动打开的设置／选关仍使用原面板。

V1.3 按盒型校验初始装量，支持逐颗 `hidden` 标记。按用户后续界面反馈，正式100关恢复每种道具各1次并显示角标；撤回恢复完整事务，加餐盒开启下一预设周转位，置顶在选择有效下层后扣次。备货展示已移除，队列和逐盒补货顺序保留。数字机关多目标时轻亮最靠前数字。停滞提示可关闭、可配置，不暂停炸弹。当前数值依据及实际验收见 [R2 更新](../../../../Designing/r2_level_update.md)；R2 装量不再叠加旧版 48／49 关修正。

补货飞行持续 0.45 秒。含补货的事务展示完毕前暂停接收新棋盘手势，防止连点或拖拽跳过侧边进入画面；取消、缩放和离树仍清理临时精灵并恢复实际局面。普通搬运的连续操作不受此限制。
