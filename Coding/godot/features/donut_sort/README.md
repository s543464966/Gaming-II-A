# 甜甜圈排序结构

`donut_session.gd` 是关卡实例的唯一状态入口。玩家操作在这里原子提交，连续回收按盒位顺序结算，并产生带快照的事件；撤回恢复整个操作。`donut_level.gd` 只加载和校验 `game_content/donuts/levels/` 中的静态定义。

每个功能目录同时维护规则与该功能专用的 `ui/` 场景和脚本：

| 目录 | 职责 |
| --- | --- |
| `board/` | 连续同味搬运、容量和盒位规则；棋盘、餐盒、手势界面及 v7 纸盒素材。 |
| `donuts/` | 甜甜圈素材入口与盒内堆叠界面。 |
| `orders/` | 需求、匹配及显式解锁规则；四卡底板默认左二接单、右二锁定。 |
| `currency/` | 本关金币只读视图；金额来自会话快照，不保存第二份余额。 |
| `settings/` | 齿轮入口及设置面板；维护三列十关选择、重开、返回与宿主侧边栏入口。 |
| `dispatch/` | 同味整盒打包匹配；常驻纸盒界面。会话负责回收、机关和原位补货的执行顺序。 |
| `presentation/` | 跨模块的已提交事件时间线与临时飞行动效。 |
| `tools/undo/` | 完整快照历史及撤回按钮。 |
| `tools/add_box/` | 固定周转盒位的选择、通关归还额外空盒的规则及加餐盒按钮。 |
| `tools/top/` | 下层置顶规则、按钮和选择界面；已知层显色，未知层可盲选。 |
| `tools/ui/` | 组合三个道具按钮、转发操作意图，并维护共用按钮底板和次数角标。 |

根 `ui/donut_sort_screen.tscn` 是页面唯一装配点，只摆放各模块的根场景及页面公共控件，不维护模块内部的金币、设置、盒位、订单进度、订单卡或道具按钮布局。`ui/donut_sort_screen.gd` 连接模块与会话并处理页面生命周期；`ui/donut_background.tscn` 组合完整的店铺与木台背景，`ui/art/` 保存页面专属素材。UI 不保存第二份玩法状态。

`orders/` 维护初始开放状态，默认只开放左侧两位。右侧两位当前没有订单序列，不参与匹配或阻塞通关。会话预留 `unlock_order_slot(index)`，只负责开放状态、后续匹配、事件与完整撤回；目前没有玩家调用入口，解锁条件、费用与解锁后订单编排留待确定，重开恢复关卡初始状态。

`orders/ui/donut_orders_view.tscn` 的四张卡片直接锚定到底板原图中的卡槽边界，随底板共同缩放。`donut_order_card.tscn` 用垂直容器分配插画区和数量行，按字体实际行高预留空间，避免内容间距与底图卡槽间距各自变化。

`board/ui/donut_box.tscn` 将纸盒后层、甜甜圈、纸盒前沿和机关依次绘制。`board/ui/art/` 保存 v7 原始 PNG 和共用裁切区域，盒体设计尺寸固定为 200×157；棋盘按 5／5／5／2 排列，每行居中，末排左侧为普通空盒，右侧为加餐盒位；餐盒与甜甜圈整体等比缩放，上限 0.84，长屏的额外高度分配给行间距。`donuts/ui/donut_stack_view.gd` 定义堆叠位置，移动和补盒动效复用同一坐标。

三个道具各自在 `tools/<功能>/ui/` 维护按钮场景与专用图标；`tools/ui/art/` 保存道具共用的粉色次数角标与浅色按钮裁切资源。原始浅色按钮底板由 `design_system/art/` 共用，设置按钮也使用这份素材。`tools/ui/donut_tools_view.tscn` 负责并排布局，页面只放置道具模块根节点。

规则查询和界面显示都从会话快照取得数据。新增回收事件时，同时检查连续结算、撤回、动效中断和全部关卡完整解。工作区测试入口为 `node Testing/scripts/run_godot.mjs architecture home donut`。

关卡校验限制“初始实际盒数＋备货盒数−订单数”为 2～3。通关后 `spare_return` 事件归还道具增加的等量空容器，不计订单或奖励；和最后一步一起撤回。快照的 `won` 是通关条件的派生值，棋盘据此隐藏未启用的周转入口，恢复未通关快照时重新显示。
