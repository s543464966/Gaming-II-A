# 甜甜圈排序结构

`donut_session.gd` 是关卡实例的唯一状态入口。玩家操作在这里原子提交，连续回收按盒位顺序结算，并产生带快照的事件；撤回恢复整个操作。`donut_level.gd` 只加载和校验 `game_content/donuts/levels/` 中的静态定义。

每个功能目录同时维护规则与该功能专用的 `ui/` 场景和脚本：

| 目录 | 职责 |
| --- | --- |
| `board/` | 连续同味搬运、容量和盒位规则；棋盘、圆纸托、手势界面及保留的 v7 机关包装。 |
| `donuts/` | 甜甜圈素材入口与盒内堆叠界面。 |
| `orders/` | 需求、匹配及显式解锁规则；四个翻盖盒默认左二接单、右二去色锁定，不单独显示关卡订单数量。 |
| `currency/` | 暂时隐藏的本关金币只读视图；保留模块与素材，金额来自会话快照。 |
| `settings/` | 齿轮入口及设置面板；百关分页选择（每页十关）、重开、返回、玩法回看与宿主侧边栏入口。 |
| `learning/` | 当前机制的首次提示、图示和统一确认弹窗；是否已读由 App 注入的进度服务持有。 |
| `completion/` | 餐台底部完成反馈与末关重玩入口；页面协调自动切关及生命周期。 |
| `failure/` | 失败弹窗、无字底图与插画、中英文标题和按钮文字；只转发导航和重试意图。 |
| `dispatch/` | 同味整盒打包匹配。会话负责回收、机关和原位补货的执行顺序。 |
| `presentation/` | 跨模块的已提交事件时间线与临时飞行动效；满足订单的甜甜圈逐颗飞至对应订单盒上方，垂直下落并被盒前沿遮住，全部收入后再更新订单；首批与补位餐盒按目标所在半区，从左右可见边界外等比水平移入；备货队列不在界面展示。 |
| `tools/undo/` | 完整快照历史与撤回规则。 |
| `tools/add_box/` | 固定周转盒位的选择及通关归还额外空盒的规则。 |
| `tools/top/` | 下层置顶规则和底部内嵌选择界面；已知层显色，未知层可盲选。 |
| `tools/ui/` | 集中维护三个按钮场景、图标、次数角标与整排布局，转发操作意图。 |

根 `ui/donut_sort_screen.tscn` 是页面唯一装配点，只摆放各模块的根场景及页面公共控件，不维护模块内部的金币、设置、盒位、订单卡或道具按钮布局。`ui/donut_sort_screen.gd` 连接模块与会话、处理页面生命周期，并统一分配安全区内各模块的区域；App 不承载总体布局。`ui/donut_background.tscn` 组合完整的店铺与木台背景，`ui/art/` 保存页面专属素材。UI 不保存第二份玩法状态。

`orders/` 维护初始开放状态，默认只开放左侧两位。右侧两位当前没有订单序列，不参与匹配或阻塞通关。会话预留 `unlock_order_slot(index)`，只负责开放状态、后续匹配、事件与完整撤回；目前没有玩家调用入口，解锁条件、费用与解锁后订单编排留待确定，重开恢复关卡初始状态。

失败由会话 `is_failed()` 派生，目前由未解除炸弹超时触发。炸弹盒首次凑齐四颗同味即转为普通盒，标识与倒计时消失；没有对应订单时留在原位等待，单纯搬空不解除，撤回归纳会恢复原炸弹与原截止时间。无可移动位置时保留补救入口，不直接判失败；停滞时轻提示周转盒。炸弹设置、教学、后台及系统演出期间暂停，普通搬运动画计时，撤回不返还时间。遮罩阻止棋盘与道具操作，返回键不关闭失败弹窗。Try Again 重开当前关卡并重置奖励与道具；Home 只发出页面的 `home_requested` 信号，保留面板和重试入口，等待后续主页导航接入。

`orders/ui/donut_orders_view.tscn` 以固定间距组合四个独立翻盖盒；`donut_order_card.tscn` 将专用正俯视口味贴纸放在盒盖中。甜甜圈、锁及完成勾号共用 `LidContent` 中心 (110, 83)，对应原图波浪背景贴纸的可见中心，文字最小尺寸变化也向两侧扩展，避免偏移。锁定位用 Shader 完整去色，完成后显示勾号。台面在订单盒前方微遮盒底，不遮口味或状态；`STICKER_ART` 与棋盘十五种口味 ID 对应，场内继续使用独立的立体食物纹理。

页面统一使用宿主逻辑像素分配空间，再换算到 1024 宽的模块设计坐标。主舞台只按可用宽度缩放，不再强制高宽比；顶部设置靠左并保持 44×44，标题优先居中，胶囊附近空间不足时收窄或下移标题。订单最大宽度 480，最短屏收至 240；道具按实际按钮与角标预留高度。柜体占高 18～56，背景只接收台面上沿、棋盘下沿和柜体下沿，不返回玩法边界。全关卡对称留白及满层空间继续由 `board/` 负责。当前视觉与验收见 [UI 对齐](../../../../Designing/ui_alignment.md)。

失败弹窗在避开胶囊后的安全矩形内居中，宽度不超过该矩形的 80%／360 逻辑像素，高度不超过 58%；保留图片等比缩放和原按钮交互。设置、教学和确认弹窗沿用各自既有尺寸，不受该限制影响。

失败弹窗的标题、副标题、返回主页和重试文案由 `game_content/localization/failure_*.po` 唯一维护，使用 Godot 原生翻译，支持简体中文和英语；地区代码自动匹配，其他语言回退英语。桌面及普通浏览器跟随系统语言，小游戏由页面初始化时调用 `platforms/minigame/host_locale.gd` 读取微信／抖音宿主语言，不依赖启动器的默认语言。运行中修改 `TranslationServer` 的语言会自动刷新已显示的 Labels；当前没有新增语言选择入口，其他界面尚未整体翻译。英文沿用 Lilita One，中文使用随包字体回退。带字原图保留，运行场景改用无字衍生图，来源、路径和生成提示词见 `failure/ui/art/asset_manifest.json`。

`board/ui/donut_box.tscn` 组合圆纸托、甜甜圈和机关，纸托设计区 200×126。棋盘按 `game_content/donuts/layouts/board_layouts.json` 创建实际数量的盒位，前十关为 6～9 个；所有关卡按最多五盒一排均摊余数，优先四至五盒，16～20 盒时使用四排；布局等比缩放，最大系数 1.08。先按满四层抬起及机关下沿压缩排间多余预留，保持行数、横坐标和索引，再按开局整排边界计算对称留白。每侧至少为最大可见排间隙的 1.05 倍加 4 个随盒缩放的单位，高度富余时按 1.20 倍限制行距伸展；基础上下预留共 160 设计单位，页面不再重复增加内缩。缩放与坐标不随局内食物数量改变。订单贴纸为居中的 64×64；灰色隐藏圈与普通口味采用匹配比例的素材，数字机关仅保留必要计数。动态创建的盒位由棋盘统一转发按压事件，输入路由持有同一数组引用。标题贴近安全区顶部，墙面保留窗下绿植，柜体下边框完整显示；底部三个道具初始显示“＋”，领取后各有 1 次，首批与补货从左右两侧进入固定盒位。配置与截图见 [盒位布局](../../../../Designing/board_layouts.md)。

三个道具按钮场景统一放在 `tools/ui/`，图标与粉色次数角标放在 `tools/ui/art/`；规则分别保留在 `tools/undo/`、`tools/add_box/` 和 `tools/top/`，置顶选择面板仍由 `tools/top/ui/` 维护。浅色按钮原图与唯一裁切 `button_base.tres` 归 `design_system/art/`，设置与道具按钮共用。`tools/ui/donut_tools_view.tscn` 负责三个按钮的居中并排布局：170×170 的按钮整体等比放大至 1.55 倍，中心间距 310，图标、文字、角标和点击范围一同放大。页面根据安全区高度将实际按钮边长设为 56～86 逻辑像素，并限制整排不超出内容宽度，角标单独计入底部占高；安全区内保留 16 逻辑像素的底边距。置顶选择与完成反馈使用同一底部区域，交互按钮至少 44 逻辑像素。

选中首颗固定对齐到满四层顶端再上抬 21 设计单位的位置（原抬升为 14，增加 50%），不随当前剩余 1～4 颗变化；单颗暂存位共用该基准，下层食物和纸托不动，取消恢复原层。已选中时点击可放入的同色餐盒或空盒直接搬运；点击不同色且可拿取的食物则改选新盒，旧食物落回原层，新食物抬到统一高度，不计步、不扣道具。不同色的满盒也可作为新来源；同色满盒无法接收、或异色盒因封口／冰冻／只进不出而无法拿取时，保留原选择及限制反馈。再次点击同一来源取消选择。点击搬运的首颗从当前抬起位置出发，拖拽仍承接手指落点；后续食物继续逐颗从来源盒出发。最短屏柜体装饰让出 6 逻辑像素供新增抬起预留使用，保留百关触控与对称留白要求。

收餐采用 0.12 秒错峰、每颗 0.36 秒飞行和 0.22 秒向下入盒。订单模块按自身美术裁切返回盒口区域，动效层转换到当前页面坐标，因此适配订单独立缩放。入盒用真实裁切遮挡，不通过透明度消失；连续订单按事件顺序逐批显示，收餐和补货结束前暂停新棋盘手势。暂停、隐藏、失焦、缩放和离树会终止时间线并清理临时节点，随后显示已提交状态。[实际动画预览](../../../../Archive/ReferenceImage/donut_dispatch_into_order.gif)。

规则查询和界面显示都从会话快照取得数据。新增回收事件时，同时检查连续结算、撤回、动效中断和全部关卡完整解。工作区测试入口为 `node Testing/scripts/run_godot.mjs architecture home donut hundred`。百关机制、V9 素材、存档及模拟广告范围见 [实现与验收](../../../../Designing/level_100_implementation.md)。

关卡的容器预算按“初始实际盒数＋备货盒数−订单数”核对，不再强制为 2～3。通关后 `spare_return` 事件归还道具增加的等量空容器，不计订单或奖励；和最后一步一起撤回。快照的 `won` 是通关条件的派生值，棋盘据此隐藏未启用的周转入口，恢复未通关快照时重新显示。

首次遇到机制时显示一次提示，可在设置回看；切关、重开及周转奖励使用明确确认。置顶选项仍暂时替换底部道具区，可切换餐盒或取消，取消与生命周期中断不扣次数。通关后 `completion/` 显示约 1.2 秒完成反馈，页面自动进入下一关；设置打开、隐藏、失焦或外部暂停会停住切关，恢复后重新计时，旧导航不会重复执行。第 100 关保持完成餐台并提供重玩按钮。失败与玩家主动打开的设置／选关仍使用原面板。

V1.3 按盒型校验初始装量，支持逐颗 `hidden` 标记。正式 100 关三种道具初始次数为 0，角标显示“＋”。首次点击只领取 1 次使用点，角标变为“1”；再次点击才执行，置顶在选择有效下层后扣次。每种道具每次尝试只能领取一次，用完隐藏角标并禁用；撤回恢复棋盘事务但不返还任何道具，存档保留领取和消耗记录，重开或切关恢复未领取状态。关卡页面的 `tool_reward_provider(tool, completed)` 是激励广告预留边界，`completed(rewarded)` 只负责确认是否获得奖励；当前未接 SDK 时临时直接发点。会话用请求类型、尝试编号和唯一序号拒绝重复或过期回调。取消可重试，隐藏、暂停、离树或替换会话会撤销请求；广告造成的失焦保留请求。备货展示已移除，队列和逐盒补货顺序保留。数字机关多目标时轻亮最靠前数字。停滞提示可关闭、可配置，不暂停炸弹。当前数值依据及实际验收见 [R2 更新](../../../../Designing/r2_level_update.md)；R2 装量不再叠加旧版 48／49 关修正。

补货飞行持续 0.45 秒。含补货的事务展示完毕前暂停接收新棋盘手势，防止连点或拖拽跳过侧边进入画面；取消、缩放和离树仍清理临时精灵并恢复实际局面。普通搬运的连续操作不受此限制。
