# 游戏内容

`donuts/levels/catalog.json` 是关卡目录，指向十份人工维护的 `level_01.json`～`level_10.json`。由 DonutLevel 校验、DonutSession 实例化；运行配置没有第二套生成来源。

## 关卡字段

- `slots`：固定 17 项，类别 `regular`／`turnover`／`single`；`unlock_after` 为消除阈值，周转固定 -1 并由道具解锁。`box: null` 表示没有容器；有盒但 `items: []` 表示空盒。
- `box`／`stock` 中的盒子：`kind` 为 `normal`／`lid`／`frozen`，`lid` 为剩余开盖计数；食物数组按顶部到下部排序，每颗只定义 `flavor`。口味 0／1／2／3／4／5／6 对应草莓彩糖／巧克力坚果／抹茶淋面／蓝莓／柠檬淋面／香草彩糖／紫色彩糖。会话记录每颗甜甜圈是否已揭示；初次露顶后保留明牌，不因堆叠回退，不在关卡中重复配置。
- 盒内 `hidden_layers`：可选布尔值，默认 `false`，全盒明牌；设为 `true` 时，下层初始灰色，可操作顶层揭示。揭示状态跟随甜甜圈，已知食物放入该盒不会变灰；补货按新盒自己的配置初始化，不继承原盒效果。
- `demands`：固定 4 项，各有独立 `sequence` 和可选布尔 `initially_open`；未配置时只开放左侧两位，只推进本次完成的位置。当前十关全部需求排入左侧两位，右侧两位序列为空且锁定。订单位不再使用 `unlock_after`，解锁条件尚未接入；运行游标不写回 JSON。
- `stock`：有限、有顺序的整盒队列，每次可补位回收消耗一盒。出场前不占棋盘格。
- `tools`：三种道具初始次数，当前默认撤回、加餐盒、置顶各 1 次；`combo_rewards`：按回收盒数递增的奖励档，使用最高符合档位，具体规则见 [基础玩法](../../../Designing/basic_gameplay.md)。

每关至少包含 7 种甜甜圈，当前十关开局都能拿取全部 7 种口味；左侧两个开放需求位通过后续序列覆盖全部口味。新增柠檬、香草和紫色彩糖使用已收录原图，订单、餐盒、拖拽及出餐共用同一纹理映射。

层序采用固定混排，开局不随机洗牌。初始盒与备货分别验收：满盒中 `AABB` 不超过四分之一，至少四分之三的满盒含 3～4 种口味；有 4 个以上满盒时还需覆盖至少三种层序结构及 `ABCD`。前三关初始 `AABB` 为 1／13、1／13、1／12 盒；三四色满盒分别为 11／13、12／13、11／12，覆盖 `ABCD`、`AABC`、`ABBC`、`ABCC`、`ABAC` 等结构。备货全部装满，三四色混排占多数。完整解步数用于回归，不代表最少步数。

当前十关各启用一个初始隐藏层盒：第一关第 1 行第 5 列，第二、三关第 1 行第 3 列；第 4～10 关的位置由各自配置决定。其余初始盒与全部现有备货保持明牌；盒位从左上角按 5／5／5／2 的行序排列，短排居中。

第 1～6 关装入 52／64 个容器容量，除第三关有两个普通空盒和两个半满盒外，各留三个普通空盒；第 7～10 关装入 56／64，各留两个普通空盒。左侧两需求开放，右侧两位保留锁定；数字盖和冰冻从第三关出现。普通空盒可直接接收任意口味，不需要先使用加餐盒道具；“不设专用补货空位”不禁止配置普通空盒。备货仍只补入真实回收后的原盒位。

配置校验包含固定位置数、1～2 个周转盒初始锁定（当前十关各 1 个）、容量、口味范围、至少七种口味、隐藏层开关类型、各口味供需守恒，以及“初始盒数＋备货盒数−订单数”必须为 2～3。第 1～6 关实际通关各留三个盒子，第 7～10 关各留两个；道具新增容器在通关后等量归还。完整解、装填余量、道具盒参与搬运和出餐、归还与撤回重做、鼠标拖拽均由 `Testing/` 验证。调整依据见 [关卡容器预算](../../../Designing/early_level_balance.md)。

`donuts/art/` 保存 11 款原始甜甜圈图、未揭示层灰色图，以及已启用的 7 种口味和灰色图的 AtlasTexture。灰色图由项目内旧隐藏甜甜圈图作为形状参考生成，属于独立运行素材；旧问号图保留在页面素材库但不再显示。通用界面资源归 `design_system/`，业务页面与机关装饰归 `features/donut_sort/ui/art/`。`audio/`、`runtime/` 仍仅是框架位置。

没有 CSV 同步或语言生成入口。新增关卡需保持供需一致并补完整可解性验证，不使用旧快照作为默认数据。
